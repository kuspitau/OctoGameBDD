## Goal

Explain the 20,707 P5-T05 addition-relative-base memberships without reopening the full
P5-T03/P5-T04 population.

For each member in:

```text
active_only_vs_base
comparison_only_vs_base
```

determine whether the addition is:

```text
A. parent_absent_from_base
   The creature/gameobject parent itself is absent from the proven complete base view.

B. spawn_added_to_base_present_parent
   The parent is present in base and has a persisted base spawn_set, but this exact spawn_key is not
   a member of that base set.
```

Then measure how those classes distribute across:

- active/Turtle-selected additions;
- Octo comparison additions;
- creature vs gameobject;
- parent template;
- canonical zone/map;
- parent/zone coverage shared by both overlays vs unique to one overlay.

The task is a coverage/provenance audit. It must not decide global source authority.

## Required base-parent classification

Use the same conservative base-membership evidence contract as P5-T05.

Expected evidence interpretation:

```text
base_membership_evidence = absent_from_complete_base_view
  -> parent_absent_from_base

base_membership_evidence = spawn_set_observation
  -> parent exists in base; exact member absence is proven against that complete spawn_set
  -> spawn_added_to_base_present_parent
```

Fail closed if a member cannot be mapped unambiguously to one of those two classes.

Do not infer parent absence from an arbitrary missing row. The succeeded exact-revision
`pfquest-overlay-reconcile/1-base-evidence` complete-view batch remains the only accepted basis for
the persisted absent-parent inference already established by P5-T05.
