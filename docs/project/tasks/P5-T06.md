## Goal

Explain the 20,707 P5-T05 addition-relative-base memberships without reopening the full
P5-T03/P5-T04 population.

For each member in:

```text
active_only_vs_base
comparison_only_vs_base
```

determine whether the addition is:

```text
A. parent_absent_from_base
   The creature/gameobject parent itself is absent from the proven complete base view.

B. spawn_added_to_base_present_parent
   The parent is present in base and has a persisted base spawn_set, but this exact spawn_key is not
   a member of that base set.
```

Then measure how those classes distribute across:

- active/Turtle-selected additions;
- Octo comparison additions;
- creature vs gameobject;
- parent template;
- canonical zone/map;
- parent/zone coverage shared by both overlays vs unique to one overlay.

The task is a coverage/provenance audit. It must not decide global source authority.


## Bounded CLI

A dedicated read-only module/CLI is implemented and emits JSON plus bounded details.

Supported filters include:

```text
--pattern active_only_vs_base|comparison_only_vs_base
--addition-parent-class parent_absent_from_base|spawn_added_to_base_present_parent
--subject-kind creature_spawn|gameobject_spawn
--parent-key <native template id>
--zone-id <canonical zone id>
--overlay-coverage active_only|comparison_only|both
--overlay-coverage-scope parent|zone
--limit <N>
--top <N>
--json
--db <path>
```

`--overlay-coverage` defaults to parent grouping; `--overlay-coverage-scope zone` applies the same
coverage class to canonical zone/map grouping. This explicit scope prevents higher-level overlap
from being mistaken for spawn identity.

The DB is opened read-only.
