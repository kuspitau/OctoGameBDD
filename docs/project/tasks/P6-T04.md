## Accepted source-selection policy

Automatic managed selection is eligible only for:

```text

```

and only when the current `itemcache.wdb` raw record SHA exactly matches a persisted freshness proof.

Explicitly ineligible:

```text

historical_cache_only
unknown
```

Additional invariants:

- cache-only native IDs do not fabricate canonical item identity;
- timeout/missing is never negative item evidence;
- competing observations remain retained;
- protected/manual/custom selections are not overwritten;
- the source is explicitly partial-positive, not whole-population complete.

## Implemented promotion workflow

The local P6-T04 implementation provides deterministic plan, shadow validation and guarded promotion
modes.

Before a real write it:

1. verifies the accepted migration-13 baseline;
2. rejects forbidden SQLite sidecars/drift;
3. creates and SHA-verifies the D-029 backup;
4. acquires guarded SQLite write access;
5. applies migration 14 exactly once when required;
6. imports/reconciles only eligible planned records;
7. reruns the same import to prove idempotence;
8. validates representative queries, provenance/selections, foreign keys and integrity;
9. leaves the verified backup available for immediate rollback.

## Windows D-029 correction

The original attempt to raw-read/copy the multi-gigabyte SQLite file while SQLite byte-range locks were
already held failed on Windows at the locked-byte region.

The final validated protocol instead:

- verifies the accepted source baseline before mutation;
- copies and SHA-verifies the D-029 backup before acquiring the SQLite write lock;
- checks `PRAGMA data_version`, source size and source mtime around the copy window;
- rejects sidecars/drift;
- acquires `BEGIN IMMEDIATE`;
- rechecks guarded state before the first canonical write.

This preserves fail-closed behavior while avoiding the Windows raw-read-under-lock failure mode.
