# P0-T03 — Fixture/golden-case and audit skeleton

## Goal

Establish the small-fixture, golden-case, audit, and machine-readable summary conventions that later domain importers can reuse before P1 begins.

This task builds on the P0-T01/P0-T02 foundation. It must not introduce gameplay-domain canonical tables or require full Octo data.

## Base

- branch: `main`
- validated base commit: `587146435e44960aaebf7105979a79516102f26e`
- P0-T02 is considered validated because its implementation is present on validated GitHub `main`.

## Scope

### Fixture conventions

Define tracked fixture rules that distinguish:

- small source-shaped importer fixtures;
- project-owned synthetic golden cases used to verify cross-source semantics/audit behavior.

Golden cases must use deterministic, inspectable inputs and expected invariants. They must not depend on large/private/local data.

### Initial golden case

Add a provenance/audit golden case covering at least:

- two registered sources and successful import batches;
- a scalar conflict with an explicit canonical selection;
- a relation conflict without a canonical selection;
- legitimate multi-valued relations that must not be misclassified as conflicts;
- deterministic generic coverage counts.

### Audit CLI scaffolding

Add commands:

- `source` — inspect source registry and import summaries;
- `trace` — inspect provenance for one subject/fact;
- `conflict` — list groups with competing distinct values;
- `coverage` — report generic provenance coverage metrics.

Each command must support:

- human-readable output by default;
- deterministic JSON via `--json`.

Conflict semantics at this stage are evidence-group semantics: multiple distinct canonical JSON observation values in the same `observation_group` constitute a conflict. Distinct relation instance groups are not conflicts merely because the relation type is multi-valued.

Coverage is explicitly `generic-provenance` coverage until P1+ domain schemas make domain-specific completeness metrics meaningful.

### Machine-readable import summaries

Provide a dependency-free, reusable summary contract for persisted import batches, including:

- source key/revision;
- status;
- row counts;
- warning/error counts;
- structured details;
- deterministic JSON serialization and file writing.

## Non-goals

- no new schema migration;
- no P1 world-domain entities;
- no full Octo/pfQuest/SQL imports;
- no polished UI;
- no source-priority policy beyond the synthetic golden-case selection used for testing.

## Acceptance criteria

- existing P0 tests remain green;
- golden fixture is tracked and documented;
- audit reports preserve source/revision/batch traceability;
- conflicts distinguish resolved from unresolved groups;
- legitimate multi-valued relation groups are not reported as conflicts;
- coverage JSON is deterministic for the golden case;
- import summary JSON round-trips deterministically;
- CLI text and JSON modes are tested;
- project-memory docs are updated for the next handoff.
