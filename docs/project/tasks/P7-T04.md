## Goal

Turn the already-validated P4 recipe domain into a stable bounded consumer-facing exploration layer by
composing it with the validated P7 item/quest query surfaces.

The task makes it practical to answer questions such as:

```text
Which recipes produce this item?
Which recipes belong to this profession/skill line and required skill range?
What exact reagents and quantities does this recipe require?
How can this recipe be learned: teaching item, trainer, or quest reward spell?
Where can the teaching item be acquired?
Where are the known trainer creatures located?
What quest teaches the recipe and what is known about that quest's geography/progression?
Which learning/reagent targets are unresolved or have unknown acquisition/geography?
```

This is a read-only composition task. It is not a new recipe ingestion campaign, craft-profit model or
ownership/inventory feature.

## Existing semantics reused

P7-T04 preserves the validated P4-T02..T04 contracts and migrations 11..13:

- recipe identity is the native crafting spell ID;
- spell and skill-line identities/names remain distinct entities;
- every skill-line membership retains its native `SkillLineAbility.id` and
  `required_skill_value`;
- output effect slots retain native item IDs and nullable canonical item resolution;
- reagent slots retain native item IDs, nullable canonical item resolution and exact quantities;
- teaching-item, trainer and quest-reward-spell learning relations remain separate;
- direct vs template-expanded trainer semantics remain explicit;
- trainer cost/skill/level requirements remain independent from recipe skill requirements;
- learning proof kind and acquisition wrapper spell evidence remain explicit;
- unresolved native teaching-item/trainer/quest IDs remain evidence rather than placeholders.

P4-T04's rule against copying derived availability into primary recipe facts remains authoritative.
No architecture decision was changed by this task.

## Implemented query scope

The read model supports:

- exact native recipe/crafting-spell ID;
- case-insensitive crafting-spell name substring;
- skill-line ID/name plus minimum/maximum recipe `required_skill_value`;
- native output item ID;
- native reagent item ID;
- deterministic sort by recipe ID or name and bounded `1..1000` limit;
- `known_match` / `known_non_match` / `unknown` state selection;
- positive learning-source-kind filters for `teaching_item`, `trainer` and
  `quest_reward_spell`;
- teaching-item acquisition zone/map filters through P7-T02;
- trainer zone/map filters through P1 world locations;
- quest giver/finisher/objective zone/map filters through P7-T03.

All requested skill-line constraints must match the same concrete recipe skill-line membership.
Output/reagent predicates use preserved native item IDs so an unresolved canonical item identity does
not erase a known P4 relation.

## Detail and provenance

Returned recipe detail keeps each P4 row independently:

- identity, spell name/rank and selected identity provenance;
- all skill-line memberships and selected relation provenance;
- all output effect slots with native/canonical item IDs and explicit resolution state;
- all reagent slots with exact quantities, native/canonical item IDs and explicit resolution state;
- all teaching-item learning rows;
- all direct/template trainer learning rows and trainer requirements/cost;
- all quest reward spell learning rows;
- acquisition wrapper spell ID/name, `learning_proof_kind`, `learn_effect_index` and
  `server_learn_active` where applicable;
- selected source/revision/record/selection evidence already recorded by P4.

P7-T04 does not create a new source-selection policy.

## Composition semantics

### Teaching item

The primary P4 fact remains:

```text
recipe -> teaching item
```

For a resolved teaching item, P7-T04 calls the validated P7-T02 acquisition surface. Direct loot,
reference loot and vendor paths therefore remain derived item acquisition evidence. Per-path drop
chance stays per-path; vendor metadata is not reinterpreted as chance.

No known path is reported as `unknown`/not-proven, not as proof that the item cannot be acquired.

### Trainer

The P4 relation remains `recipe -> trainer creature`. P7-T04 preserves direct/template semantics,
native trainer entry, nullable creature resolution, template ID and trainer requirements. Known
locations are derived using the existing P1 world-location query. An unresolved trainer or resolved
trainer with no known spawn remains valid learning evidence with unknown geography.

### Quest reward spell

The P4 relation remains the quest reward spell learning source. A resolved quest composes P7-T03 quest
detail; giver, finisher, objective and progression semantics remain separate. An unresolved quest ID
remains unresolved evidence.

## Coverage and negative-evidence rule

P7-T04 is an exploration layer, not a new source authority layer.

Exact P4 identity/skill/output/reagent rows may prove positive or negative predicates within their
validated complete source-family semantics. Derived learning/acquisition/geography filters are
positive-evidence predicates:

- a known matching source/location proves `known_match`;
- lack of a known matching source/location remains `unknown`;
- a known-false complete P4 predicate still dominates conjunction as `known_non_match`.

The implementation does not infer additional reagents, quantities, output counts, sources or zones
from names, ID coincidence or defaults.
