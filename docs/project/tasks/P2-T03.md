# P2-T03 — pfQuest vendor acquisition (`V`)

## Status

`READY`

## Prerequisite

P2-T02 must be present on GitHub `main` and marked `VALIDATED` before implementation starts.

## Goal

Materialize the pfQuest item vendor-acquisition family that P2-T01/P2-T02 deliberately counted but
deferred, so item-source queries can expose vendors without conflating vendor evidence with loot.

P2-T01 full-data validation observed `13,860` deferred `V` relations, making this the next bounded P2
completeness gap after reference-loot resolution.

## Required primary-source investigation

Before choosing schema or field semantics, inspect the project-pinned/current relevant pfQuest
primary source for:

- the exact shape of `items[item_id]["V"]`;
- whether keys are creature/vendor IDs and what values mean;
- how pfQuest resolves/displays vendor item relationships;
- whether price, stock, limited-stock, faction or other vendor semantics are encoded elsewhere;
- whether Turtle/Octo overlay files alter the relevant item/vendor tables in a way that must be
  handled in this bounded slice.

Do not infer price/stock semantics from numeric shape alone. Preserve unknown fields as source
evidence or defer them explicitly.

## Bounded implementation target

The smallest acceptable slice should:

- preserve native item and vendor creature IDs;
- use an explicit canonical item/vendor acquisition relation rather than overloading loot tables;
- preserve provenance separately from direct/reference loot relations;
- reuse canonical P1 creature identity/spawns when available;
- allow a named vendor template to exist without invented spawn geography if the established P2
  relation-only policy applies;
- fail closed or explicitly report unresolved vendor identity when neither canonical identity nor
  authoritative source identity is available;
- extend `item-sources` (or the bounded acquisition query surface) without making derived geography
  primary truth;
- remain same-revision idempotent;
- keep reference-loot behavior unchanged.

If source research shows that price/stock are separable from the existence of a vendor relationship,
prefer getting the relationship correct first and document richer commercial terms as deferred.

## Level-1 acceptance

Use reduced source-shaped fixtures and tests covering at minimum:

- exact `V` parsing semantics established from primary source;
- migration/schema constraints for any new canonical relation;
- vendor relation provenance;
- idempotent repeat import;
- located and unlocated vendor query behavior;
- unresolved vendor identity policy;
- coexistence with direct `U`/`O` and reference `R` acquisition paths;
- CLI/query output;
- migration upgrade from schema version 5.

## Level-2 acceptance

Against the user's configured full pfQuest/Turtle inputs:

1. build/rebuild the bounded validation database with the P1 world and active Turtle reconciliation;
2. import the P2 item/acquisition slice including vendors;
3. confirm non-zero vendor coverage;
4. repeat the exact import and require zero canonical changes;
5. run `PRAGMA foreign_key_check`;
6. query at least one real vendor-derived item source;
7. trace vendor relation provenance independently from loot/reference provenance.

Prefer rebuilding the bounded dependency chain rather than trusting an arbitrary cached generated DB
unless its schema/import state has been explicitly verified.

## Explicitly deferred

Unless primary-source research proves inseparability:

- richer item stats/effects/requirements;
- item/container and specialized loot families;
- generalized economics/AH data;
- broad Turtle/Octo item overlay reconciliation;
- full P6 ingestion/performance work;
- UI.
