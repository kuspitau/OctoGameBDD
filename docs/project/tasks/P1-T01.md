# P1-T01 — World schema and pfQuest fixture vertical slice

## Goal

Establish the first bounded P1 world-foundation vertical slice with explicit canonical world tables, source-shaped pfQuest fixtures, provenance-aware materialization, and a small cross-entity location query.

This task must prove the path from source-shaped input to canonical world records without attempting full-world ingestion.

## Base

- branch: `main`
- base commit: `fc0dbe0fc22610113bfc8bd9c1e07cb41d400a39`
- P0 is treated as closed because the P0-T03 implementation and the subsequent local-path/handoff workflow amendment are both present on GitHub `main`, the project's validated source of truth.

## Public source evidence

The fixture/parser contract was checked against the archived upstream pfQuest repository at commit:

- repository: `https://github.com/shagu/pfQuest`
- revision: `104f35678ca39ab1fb78b655f815cc7016f5e0c8`
- license: MIT

Relevant source shapes at that revision:

- `db/enUS/zones.lua` maps numeric zone IDs to localized names;
- `db/zones.lua` stores zone coordinate-frame data as positional Lua tables;
- `db/enUS/units.lua` maps numeric creature IDs to localized names;
- `db/units.lua` stores unit metadata and `coords` entries shaped as `{x, y, zone, respawn}`;
- `db/enUS/objects.lua` maps numeric game-object IDs to localized names;
- `db/objects.lua` stores object metadata and `coords` entries with the same coordinate tuple shape.

pfQuest's database code consumes unit/object coordinates as percentage coordinates within a zone. The first element of a `zones.lua` geometry record is source-specific coordinate/map context; this task deliberately preserves it as provenance (`pfquest.coordinate_frame`) instead of inventing a canonical `parent_zone_id` or authoritative map relationship.

## Scope

### Canonical world schema

Add migration `0003_world_foundation.sql` with first-class canonical tables for:

- `maps`;
- `zones`;
- `creatures`;
- `creature_spawns`;
- `gameobjects`;
- `gameobject_spawns`.

Rules:

- preserve native map/zone/template IDs;
- keep creature/game-object templates separate from geographic spawn instances;
- use project-local spawn surrogate IDs plus deterministic `spawn_key` identities when the source has no native spawn ID;
- make coordinate space explicit;
- support `zone_percent` and future `world` coordinates without pretending one is the other;
- leave map/parent-zone links nullable until an authoritative source provides them.

### Source-shaped pfQuest fixture adapter

Add a dependency-free adapter for the small tracked fixture shape.

It must:

- parse only the Lua literal-table subset needed by the six pfQuest files above;
- preserve numeric native IDs;
- validate zone-percentage coordinates as 0..100;
- import names, levels/faction where represented, spawn position, respawn time, and zone coordinate-frame evidence;
- register pfQuest and an import batch with the pinned source revision;
- use the existing observation/provenance primitives;
- create a first canonical selection only for previously unselected observation groups, without silently replacing an existing explicit selection;
- materialize canonical rows idempotently.

### Golden fixture slice

Track a reduced `tests/fixtures/pfquest/world_slice/` source tree mirroring the upstream pfQuest file layout. It contains only the minimal records needed to exercise:

- a named zone plus a referenced zone;
- one creature with two spawns;
- one game object with one spawn;
- level/faction metadata;
- respawn metadata;
- source coordinate-frame metadata.

### Query slice

Add a small programmatic query that searches creature/game-object names and returns their canonical spawn location plus the source/revision selected for the canonical position observation.

## Non-goals

- no polished CLI/UI for world browsing;

- a fresh database applies migrations 1 through 3;

- creature/game-object templates remain separate from spawns;
- repeated import of the same source revision creates no duplicate canonical rows or source observations while retaining per-import-batch trace links;
- canonical position queries include selected source/revision attribution;
- existing P0 behavior remains green;
- project-memory docs identify this as the current P1 task and describe what remains intentionally deferred.
