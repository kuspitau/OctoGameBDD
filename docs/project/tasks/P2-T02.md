## Goal

Resolve the pfQuest item `R` reference-loot family so acquisition queries do not miss loot inherited
through reference tables, while preserving the explicit/provenance-aware model established by
P2-T01.

P2-T01 full-data validation observed `10,209` deferred `R` links, so this is a material completeness
issue rather than a theoretical edge case.

## Primary-source investigation result

Inspected pfQuest revision:

```text
104f35678ca39ab1fb78b655f815cc7016f5e0c8
```

Established source contract:

```text
items[item_id]["R"][reference_loot_id] = chance_percent
refloot[reference_loot_id]["U"][creature_id] = membership_marker
refloot[reference_loot_id]["O"][gameobject_id] = membership_marker
```

At that revision, `SearchItemID` expands an item `R` exactly one level through `refloot.U` and
`refloot.O`. It carries the item-side `R` chance to every resulting source and iterates refloot member
keys without interpreting the membership value as a probability/weight. The reviewed source does
not implement recursive `R -> R` expansion.

Consequences:

- chains/cycles are not part of the supported pinned contract;
- a nested `R` inside a refloot definition is treated as unsupported/malformed input and rejected;
- direct `U`/`O` and reference-derived paths are parallel acquisition evidence;
- no mathematical combination of overlapping direct/reference chances is inferred.

## Implemented bounded scope

Migration 5 adds:

```text
loot_references
item_reference_loot
reference_loot_creatures
reference_loot_gameobjects
```

The importer now:

- preserves native reference IDs;
- includes `db/refloot.lua` in the deterministic item-source revision;
- records `item -> loot_reference` relation provenance with the source-listed chance;
- records `loot_reference -> creature/gameobject` membership provenance, preserving the numeric
  member marker as provenance-only metadata;
- materializes only reference definitions actually used by accepted items;
- reports missing definitions and reference-only members without materializable source identity with
  IDs/reasons;
- preserves P2-T01 fail-closed behavior for unidentified direct targets;
- remains same-revision idempotent.

The item acquisition query now derives reference sources by joining those explicit canonical
relations. It folds a direct and reference path that reach the same source/spawn into one returned
source with multiple `acquisition_paths`. If path chances differ, source-level `chance_percent` is
`null`; each path retains its own original chance and provenance.

Geography remains derived exclusively through P1 templates/spawns/zones/maps. Reference-only source
templates may therefore be intentionally unlocated.
