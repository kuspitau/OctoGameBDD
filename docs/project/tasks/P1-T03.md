# P1-T03 — pfQuest Turtle/Octo effective world views and comparison

## Goal

Model the actual P1 world data composition used around Octo without assuming that the older `pfQuest-octo` addon is globally newer or more authoritative than the `pfQuest-turtle` currently distributed to the user.

P1-T03 builds deterministic **effective source views** only. It does not yet choose canonical winners in SQLite.

## Source evidence

### pfQuest-turtle — primary local overlay source

Repository:

```text
https://github.com/KameleonUK/pfQuest-turtle
```

Reviewed public reference revision:

```text
5b8eeeeb4119be9d075087f0f0e08c187b35ad61
```

Relevant files:

```text
pfQuest-turtle.toc
patchtable.lua
overwrites.lua
db/zones-turtle.lua
db/enUS/zones-turtle.lua
db/units-turtle.lua
db/enUS/units-turtle.lua
db/objects-turtle.lua
db/enUS/objects-turtle.lua
```

The addon depends on pfQuest, loads the Turtle tables, runs `overwrites.lua`, then runs `patchtable.lua`.

`patchtable.lua` applies top-entry replacement semantics:

- patch value exactly equal to the string `"_"` deletes the corresponding base entry;
- every other patch value replaces the corresponding base entry wholesale;
- there is no recursive merge during `patchtable` itself.

The reviewed public `overwrites.lua` also removes a documented set of phantom zone IDs from localized Turtle zone tables via a small loop. P1-T03 recognizes this specific safe pattern without executing Lua.

Level-2 validation established that the user's launcher-installed copy is not byte/behavior-identical to that reviewed public revision: its `overwrites.lua` does not contain the phantom-zone cleanup loop. Therefore the loader must reproduce a supported cleanup **only when the installed source actually declares it**; it must not invent public-revision mutations that are absent locally.

### pfQuest-octo — optional Octo-specific comparison source

Repository:

```text
https://github.com/paokkerkir/pfQuest-octo
```

Reviewed revision:

```text
dd3dc1fb80afe7a71e5c8ca8c31ca2a3ef57af67
```

The latest reviewed commit is from 2026-05-12 and is titled `db: revert to 1.17.2 data`. This makes it unsuitable as an assumed globally newer replacement for the currently maintained Turtle fork.

It remains useful because its `overwrites.lua` contains Octo-specific corrections and custom-content adjustments. P1-T03 therefore supports loading it as a second effective view and comparing it with the current Turtle view.

## In scope

- existing P1 domains only:
  - zones;
  - units/creatures;
  - objects/gameobjects;
- pfQuest base tables already parsed by P1-T01;
- Turtle-style `*-turtle` top-entry patch semantics;
- direct literal world-table assignments in `overwrites.lua`;
- the reviewed Kameleon Turtle phantom-zone cleanup loop when it is present in the loaded overlay;
- deterministic effective views for:
  - `pfQuest + pfQuest-turtle`;
  - `pfQuest + pfQuest-octo` when available;
- a comparison result reporting added, removed and changed entity IDs without selecting a winner;
- source-shaped tests;
- Level-2 validation against the user's installed addon directories.

## Out of scope

- database materialization of either overlay;
- provenance observations for overlay sources;
- canonical winner selection;
- negative/deletion provenance modeling;
- stale spawn cleanup in SQLite;
- quests/items/loot/recipes;
- arbitrary Lua execution or a general Lua interpreter;
- claiming `pfQuest-turtle` or `pfQuest-octo` is universally authoritative.

## Local path contract

Required:

```toml
[source_paths]
pfquest = "..."
pfquest_turtle = "..."
```

Optional comparison source:

```toml
pfquest_octo = "..."
```

`get_path.bat` must resolve/validate `pfquest` and `pfquest_turtle`. It may reuse or auto-detect a valid `pfquest_octo`, but absence of the optional source must not fail P1-T03.

## Acceptance criteria

1. No Lua is executed.
2. pfQuest base tables and matching optional `*-turtle` tables are composed deterministically.
3. `"_"` deletes a top-level entry; other patch values replace it wholesale.
4. Direct literal `overwrites.lua` assignments for in-scope world tables are applied before composition.
5. A supported Turtle phantom-zone cleanup is reproduced safely when present, and is not invented when absent.
6. An unrecognized indirect world-table mutation fails closed with `PfQuestParseError`.
7. Existing zone-percent coordinate validation is reused unchanged.
8. `pfQuest + pfQuest-turtle` and `pfQuest + pfQuest-octo` can be loaded independently.
9. Comparison reports added/removed/changed IDs and does not choose a canonical winner.
10. No schema migration is introduced.
