# P7-T02 — provenance-aware item acquisition/source exploration

Status: `READY_FOR_IMPLEMENTATION`

Base branch: `main`

Routing prerequisite: P7-T01 is fully integrated/committed as `VALIDATED`, including its query
contract, read-only CLI and tests.

## Goal

Compose the validated P7-T01 item predicate surface with the already-validated P2 acquisition graph so
an item query can expose and positively filter known acquisition paths, source geography and drop
chance without inventing completeness or probability semantics.

This is the next bounded step toward project queries such as:

```text
items satisfying template/stat predicates
AND obtainable through a known source of a requested type
AND/OR through a known source in a requested zone/map
AND/OR with a known path drop chance >= threshold
```

## Existing semantics to reuse

Do not redesign the P2 model. Reuse the existing primitive and derived contracts:

- direct creature loot;
- direct game-object loot;
- reference-loot membership expansion;
- vendor acquisition;
- source/spawn -> zone -> map geography;
- existing `find_item_sources()` behavior and its per-source `acquisition_paths`;
- separate provenance for primitive acquisition relations;
- no invented combined drop probability when multiple paths reach the same source;
- unresolved reference definitions/targets and unlocated sources remain explicit diagnostics/unknown
  geography rather than fabricated rows.

P7-T01 remains authoritative for item-template/stat predicate states and bounded deterministic result
output.

## Required scope

At minimum, design and test a stable library/CLI composition layer that can:

- attach known P2 acquisition sources/paths to P7-T01 item results;
- preserve direct/reference/vendor path type explicitly;
- expose source template identity/name where known;
- expose known path-level drop chance without combining competing paths;
- expose spawn/zone/map context when derivable from the canonical P1 geography;
- preserve unlocated known sources as valid acquisition evidence with unknown geography;
- positively filter known paths by source/acquisition type;
- positively filter known path drop chance by minimum threshold where chance exists;
- positively filter known geography by zone and/or map native ID;
- return deterministic ordering and bounded output;
- expose selected primitive acquisition provenance sufficient to audit why a path is present;
- compose cleanly with P7-T01 item predicates rather than duplicating their implementation.

The implementation may add a new focused module/CLI or extend the current P7 surfaces, whichever keeps
responsibilities clearest after inspecting current callers/tests.

## Coverage / negative-evidence rule

A missing acquisition path must **not** automatically become proof that an item cannot be acquired by
that method or in that geography.

Before exposing any item-level `known_non_match` for acquisition/source predicates, inspect the
available P2-T04 complete-set evidence and P1 spawn-set coverage and prove that the relevant negative
claim is actually supported. If completeness cannot be established for the exact predicate, return or
retain an explicit unknown/not-proven state instead of silently excluding the item.

Examples:

- a known vendor with no spawn is a known vendor acquisition with unknown geography;
- a known creature loot path whose creature has no canonical spawn does not prove the item is absent
  from every zone;
- multiple direct/reference paths with different chances remain separate path facts;
- vendor `max_count` is not drop chance;
- absence of a path in a partial source view is not universal non-acquisition evidence.

If the existing provenance model cannot express the required completeness distinction without a new
architecture/schema decision, stop and route that as a separate bounded task rather than weakening
semantics inside P7-T02.

## Constraints

- Read-only consumer task: no canonical DB mutation.
- No schema migration unless a concrete query requirement proves the current model insufficient; if
  so, stop and route a separate schema task.
- No automatic P6 acquisition/promotion tranche.
- No new global source-priority rule.
- Preserve protected selections and competing source observations.
- Preserve native IDs and template/spawn separation.
- Do not persist `item -> zone` as primary truth; geography stays derived from acquisition source
  spawns.
- Do not combine path probabilities without an explicit validated probability model.
- Keep output deterministic and bounded.

## Validation expectations

### Level 1

Use tracked/source-shaped fixtures to cover at least:

- P7-T01 template/stat predicate + acquisition composition;
- direct creature loot;
- direct game-object loot;
- reference-loot path;
- vendor path;
- direct/reference overlap reaching the same source with separate acquisition paths;
- differing chances with no invented source-level combined chance;
- located and unlocated sources;
- zone/map filters;
- minimum drop-chance filtering;
- acquisition-type filtering;
- provenance trace;
- deterministic ordering/limits;
- conservative unknown behavior where negative acquisition/geography cannot be proven;
- CLI/JSON output if a CLI surface is added/extended.

### Level 2

Run read-only against the accepted canonical DB and demonstrate representative real queries combining
P7-T01 item predicates with P2 sources/geography. Verify the canonical SHA remains byte-identical
before and after validation.

Expected accepted baseline at task start:

```text
schema_version=14
canonical_sha256=60aeb4093fa68e6b3a7a8c513e5a127862d88db8bc9aab4f6f3e4a0f4c0d5a23
```

## Non-goals

P7-T02 does not implement:

- weapon damage/speed/block ingestion;
- item spell/effect ingestion;
- weighted stat/build scores;
- saved searches;
- ownership/inventory/bank integration;
- generalized recipe traversal;
- quest-chain explorer;
- graphical maps/UI;
- new acquisition source ingestion beyond the already-modeled P2 families.

Those remain later bounded tasks.
