## Goal

Compose the validated P7-T01 item predicate surface with the already-validated P2 acquisition graph so
an item query can expose and positively filter known acquisition paths, source geography and drop
chance without inventing completeness or probability semantics.

This is the bounded step toward queries such as:

```text
items satisfying template/stat predicates
AND obtainable through a known source of a requested type
AND/OR through a known source in a requested zone/map
AND/OR with a known path drop chance >= threshold
```

## Existing semantics reused

P7-T02 does not redesign P2. It reuses `find_item_sources()` and therefore preserves:

- direct creature loot;
- direct game-object loot;
- one-level reference-loot membership expansion;
- vendor acquisition;
- source/spawn -> zone -> map geography;
- separate `acquisition_paths` when direct/reference overlap reaches one source/spawn;
- primitive relation provenance and reference-member provenance;
- no combined probability across competing paths;
- unlocated sources as valid acquisition evidence with unknown geography.

P7-T01 remains authoritative for item identity/template/stat predicate states and deterministic item
sorting/output semantics.

## Coverage / negative-evidence contract

P7-T02 uses existential positive evidence for acquisition/source/geography predicates.

For one item:

```text
known concrete source/path satisfies every requested acquisition/geography condition
    -> acquisition state = known_match

no known concrete source/path satisfies every requested condition
    -> acquisition state = unknown
       reason = no_known_matching_path_negative_not_proven
```

P7-T02 deliberately does **not** emit item-level acquisition `known_non_match` from path/geography
absence. The currently modeled P2/P1 source-view completeness facts do not justify a universal
negative for these arbitrary consumer predicates.

Combined conjunction preserves P7-T01 ordering:

1. a P7-T01 `known_non_match` item predicate dominates -> combined `known_non_match`;
2. otherwise a P7-T01 `unknown` remains combined `unknown`;
3. otherwise a known acquisition match -> combined `known_match`;
4. otherwise -> combined `unknown`.

This preserves the task's examples:

- a known unlocated vendor can match `path_kind=vendor`, but a requested zone/map remains unknown;
- a known loot source without a spawn does not prove absence from every zone;
- direct/reference overlap retains separate paths/chances;
- `vendor_max_count` is never considered by `min_drop_chance`;
- unresolved/missing acquisition materialization cannot become universal negative evidence.

## Query composition / bounding

A P7-T01 page is bounded to at most 1000 returned rows. P7-T02 therefore must not first obtain a
truncated P7 page and then post-filter acquisition, because that could miss later matching items.

When acquisition filters are active, P7-T02 reuses the P7-T01 internal evaluator over the canonical
item universe, evaluates acquisition evidence before the final sort/limit, then applies the same P7
sort semantics and the requested `1..1000` result limit. Summary state counts remain exhaustive over
canonical item identities.

When no acquisition filter is active, P7-T02 delegates directly to `query_items()` and attaches
`find_item_sources()` results only to the already selected P7 page.
