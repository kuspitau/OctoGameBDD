The implementation reuses P5-T03's persisted comparison helpers and does not load raw addon sources.
It treats `spawn_set` as the unique membership source of truth for this audit, then uses selected child
`position` observations only to expose active-only provenance. Primitive `position` and
`respawn_seconds` groups are not counted again as membership differences.

Relocation analysis intentionally uses **no identity threshold**. For every one-sided member it:

1. considers only opposite-direction members of the same subject kind and parent template;
2. requires the same coordinate space and compatible geographic context (`zone_id` for
   `zone_percent`, canonical `map_id` for `world`);
3. treats every coordinate-compatible opposite member as analytical candidate evidence without a
   proximity identity threshold;
4. computes deterministic Euclidean distance when coordinates permit it and exposes the nearest
   candidate subset separately;
5. retains every equal-distance nearest neighbour, preserving nearest-neighbour ambiguity;
6. reports descriptive distance bands by coordinate space;
7. never merges identities or labels a candidate a proven relocation.

Review found a P5-T04 implementation mismatch with P5-T03 set semantics: P5-T03 reduces a
`spawn_set` to unique `spawn_key` membership, while P5-T04 rejected an entire parent when a persisted
complete-set list repeated the same `spawn_key`. The pfQuest-family complete-set builder sorts but
does not deduplicate payload rows, so exact duplicate coordinate rows are legal persisted evidence.

The hotfix therefore collapses repeated `spawn_key` values to one unique membership, preserving the
first deterministic payload for coordinate/provenance analysis. A regression fixture now includes a
duplicate comparison-side `spawn_key` while retaining the same expected unique membership totals.
The Level-2 validator also prints the complete observed membership baseline before asserting fixed
counts, so any further mismatch will be directly diagnosable from the main log.

P5-T04 remains `IMPLEMENTED_AWAITING_LOCAL_VALIDATION` until the corrected Level-2 run passes.

## Relocation-candidate analysis

Because coordinate-bearing identity can turn a move into one removed + one added key, P5-T04 should
provide a **candidate** relocation analysis.

Constraints:

- only compare opposite-direction one-sided spawns within the same subject kind;
- require the same parent template;
- require compatible coordinate space and the same zone/map context;
- compute deterministic geometric distance when the coordinate semantics permit it;
- report distance bins and bounded nearest candidate pairs;
- do not automatically merge, rewrite, or declare two spawn identities equivalent;
- do not choose an arbitrary single threshold and call every match below it a true move.

Prefer reporting several deterministic distance bands, for example derived from the coordinate space,
so later evidence can choose a justified threshold.

If nearest-neighbor matching can be ambiguous, preserve ambiguity rather than greedily inventing
identity.

## Required aggregates

At minimum:

- total unique shared / active-only / comparison-only members;
- counts by creature/gameobject;
- counts by parent template;
- counts by zone/map;
- counts by active selected source/revision/policy;
- number of parents with active-only, comparison-only, and mixed membership;
- distribution of one-sided member counts per parent;
- relocation-candidate counts by distance band;
- number of one-sided members with zero, one, or multiple plausible opposite-direction candidates;
- top bounded parent/zone concentrations;

### Closeout routing decision

P5-T04 does not support outcome 1 ("most differences reduce to plausible coordinate relocations"):

- 54.29% of one-sided members have no coordinate-compatible opposite;
- only 6.90% have exactly one compatible candidate;
- 38.81% have multiple candidates;
- compatible-pair distances are dominated by `>5` zone-percentage-point possibilities.

The population is also strongly source/zone structured:

- 22,264 / 22,295 one-sided memberships belong to an active `pfquest-turtle` complete-set context;
- the top 10 zone/direction buckets contain 73.50% of one-sided memberships;
- the top 10 individual parents contain only 10.47%.

This is consistent with source-view/content-set divergence being a major factor, but P5-T04 cannot
attribute each membership to the Turtle side or Octo side relative to the common base view.

Route to:

```text
P5-T05 — three-way base/Turtle/Octo spawn divergence attribution
```

P5-T05 should use persisted provenance to classify the 22,295 one-sided members by base/active/
comparison membership vector before any source-authority or coordinate-identity decision.

D-025 and D-026 remain unchanged. `pfquest-octo` remains comparison evidence only.
