## Why this bounded task was selected

The project goal is an external local application for querying and exploring interconnected OctoWoW
data. The data/provenance/query layers were mature enough for a first graphical consumer, and P7-T07
reduced representative zone-detail latency from roughly 19-38 seconds to 5-8 seconds.

A zone-centric slice was the safest first UI surface because P7-T06 already composes:

- canonical zones/maps;
- creature/gameobject spawns;
- direct/reference/vendor item acquisition;
- quest giver/finisher/objective roles;
- vendors and trainers;
- compact positive recipe-learning evidence;
- explicit unknown/truncation semantics.

This was a UI/application task, not a new data-model or ingestion task.

## Framework decision

P8-T01 reviewed current primary documentation for NiceGUI, Streamlit and Reflex and selected NiceGUI
under D-038.

Reviewed evidence included:

```text
https://github.com/zauberzeug/nicegui/releases/tag/v3.16.0
https://nicegui.io/documentation/
https://docs.streamlit.io/develop/concepts/design/multithreading
https://reflex.dev/docs/events/background-events/
https://reflex.dev/docs/library/tables-and-data-grids/data-table/
```

The bounded reasons were:

- NiceGUI is backend/Python-first and runs a local browser server without a separate frontend build;
- `ui.table` supplies the table/pagination direction needed while P7 retains sort/filter ownership;
- `run.io_bound()` keeps multi-second SQLite reads off the UI event loop;
- `nicegui.testing.user_simulation` permits fast Python-level UI interaction tests without Selenium;
- pages/routing and future richer components are available without introducing an API split.

Runtime dependency:

```text
nicegui>=3.16,<4
```

## Implemented bounded scope

The task added:

```text
src/octogamedb/ui_read.py
src/octogamedb/ui_app.py
tests/test_ui_read.py
tests/test_ui_app.py
```

`ui_read.py` is the only UI-facing database adapter. It:

- requires an existing DB file;
- opens it through SQLite URI `mode=ro`;
- enables `PRAGMA query_only=ON` and validates that the SQLite header/schema is readable;
- calls P7 `query_zones()` / `zone_query_page_to_dict()` for list/search;
- calls P7 `inspect_zone()` for detail;
- reshapes only already-validated P7 outputs into scalar display rows.

`ui_app.py` contains no canonical-domain SQL. It provides:

- initial zone list plus ID/name/map filters;
- query-layer sort field/direction controls;
- explicit inclusion controls for P7 unknown/known-non-match states;
- list-to-detail navigation;
- entity, item, quest, vendor, trainer and recipe evidence sections;
- a coverage card exposing unknown/truncation/non-negative-claim semantics;
- a visible `Loading zone detail…` state;
- `run.io_bound()` around P7 reads;
- clear missing/unreadable DB errors without creating a DB.

Startup commands are:

```text
octogamedb-ui --db data/generated/octogamedb.sqlite3
python -m octogamedb.ui_app --db data/generated/octogamedb.sqlite3
```

No migration, persistent UI state, remote service, API split or canonical mutation was added.

## Semantic and architecture constraints preserved

- P7 remains owner of query/filter/sort/three-state semantics.
- No UI-side canonical SQL truth was introduced.
- Native IDs and template/spawn separation are preserved in display rows.
- Direct/reference/vendor acquisition paths remain separate in the underlying P7 payload.
- Quest giver/finisher/objective buckets remain separate.
- Resolved and unresolved trainer relations remain separate.
- Recipe teaching-item, trainer, giver, finisher and objective evidence remain separate sections.
- Coverage state and truncation are displayed explicitly; empty tables warn that absence of positive
  evidence is not a universal negative.
- `zone -> everything` remains a runtime derived projection only.

## Level-1 validation and correction

The initial local gate exposed three failures:

1. the NiceGUI user-simulation test tried to search `QTable` cell text that the simulation does not
   expose as searchable page text;
2. two pre-existing P4 fixture tests failed only because pytest was invoked with
   `--basetemp=.pytest_tmp`, placing tiny non-Git fixture trees underneath the parent OctoGameDB Git
   checkout. The P4 importer correctly walked up to that real parent checkout and therefore saw the
   OctoGameDB revision rather than treating the fixture as a standalone non-Git tree.

The correction deliberately did **not** alter P4 semantics. It changed only P8 files:

- zone navigation links now include the zone name and remain marker-addressable;
- the NiceGUI test validates the visible navigation link rather than table-cell text;
- Ruff `PLC0206` and two `SIM117` findings were fixed.

The user then reran the automated gate with an external pytest basetemp and reported that all tests
pass.

## Level-2 browser/full-data validation

The real UI was run against:

```text
data/generated/octogamedb.sqlite3
```

The user confirmed:

- zone list display works;
- zone-ID search works;
- zone-name search works;
- map-ID/map-name search works;
- ascending/descending query-layer sorting works;
- zone detail navigation works;
- `Loading zone detail…` is visible during the multi-second P7 read;
- expandable world-entity, item, quest, vendor, trainer and recipe sections render;
- incomplete coverage remains explicit.

A concrete Blasted Lands detail view showed the expected semantics, including:

```text
Negative claim authorized: False
Unknown entity geography: 0
Known non-matches: 34490
Returned entities: 319
Recipe geography remaining unknown:
  teaching_item=1562
  trainer=1739
  quest_giver=1739
  quest_finisher=1739
  quest_objective=1739
```

This confirms that the UI does not convert missing/incomplete evidence into universal negative claims.

The machine was restarted after the original `$before` hash variable was captured, so that shell
variable was lost and a literal `$before -eq $after` comparison later returned `False` only because
`$before` was empty. After the UI had been run and stopped, the canonical DB was hashed again as:

```text
60aeb4093fa68e6b3a7a8c513e5a127862d88db8bc9aab4f6f3e4a0f4c0d5a23
```

This exactly equals the accepted canonical baseline recorded before P8-T01. The read-only validation
therefore passes and the canonical DB did not advance.

Stopping NiceGUI/Uvicorn with `Ctrl+C` on Windows/Python 3.13 produced a `CancelledError` followed by
`KeyboardInterrupt`; this is shutdown noise from interrupting the server loop and did not affect the
DB hash or task result.

## Observed non-blocking UX limitations

The browser validation also identified interaction friction which is **not** a P7 semantic defect:

- pressing Enter in a search input does not submit;
- sort/state-control changes require an explicit `SEARCH` click;
- the separate row of `Open <zone> (...)` links below the table is functional but awkward;
- zone-detail loading remains visibly multi-second because it consumes the validated P7 read path.

These concrete observations route P8-T02. They do not reopen P8-T01 validation.
