## Goal

Add the first stable bounded first-class creature/gameobject consumer surface. It searches canonical
P1 templates, keeps every spawn independent, evaluates conservative spawn geography and composes
validated P2 item/vendor, P3 quest-role/objective and P4 trainer relations without flattening source
semantics.

promotion, route planner or graphical UI.

## Implemented query scope

The bounded query supports:

- `creature` / `gameobject` kind;
- exact native/canonical entity ID;
- case-insensitive canonical name substring;
- derived P1 spawn zone and/or map filters;
- explicit `known_match`, `known_non_match`, `unknown` states;
- deterministic sort by entity ID, name or kind;
- bounded `1..1000` limit;
- deterministic JSON-friendly detail.

Returned detail exposes only existing canonical template fields, every canonical spawn independently,
selected spawn/world-presence provenance and the cross-domain relations described below.

## Geography rule

P7-T05 preserves D-026 rather than introducing a world-source union.

A matching canonical spawn proves `known_match`. A selected `spawn_set` can prove a bounded
`known_non_match` only when its **distinct `spawn_key` identities** exactly cover the current canonical
materialized spawn view for that entity and every requested geography component is resolved.

Selected source evidence may contain duplicate entries for one `spawn_key`. P7-T05 preserves the raw
selected payload in provenance and reports duplicate counts/keys, but compares membership by distinct
`spawn_key` because the canonical spawn identity is keyed that way. Duplicate source entries therefore
do not fabricate additional spawn instances and do not by themselves invalidate complete-set coverage.

The following remain `unknown` negatives:

- no selected complete spawn set;
- a selected member is missing from canonical materialization;
- a protected/custom canonical spawn exists outside the selected set;
- requested zone/map context is unresolved for any member needed to prove the negative.

An empty selected complete set can prove a negative only for that selected effective P1 source view;
it is not a universal absence statement.

## Cross-domain role composition

### Item acquisition

The entity view reverses existing P2 materialized relations only:

- direct creature/gameobject loot;
- reference-loot source membership;
- vendor creature relations.

Per-path chance is preserved. Direct and reference paths remain separate and are never probability
combined. Vendor `max_count` is read from the selected `vendor_source` relation payload and remains
separate from chance.

### Quests

Giver, finisher and objective roles remain distinct. P7-T05 returns materialized P3 roles plus selected
endpoint/objective evidence for the inspected entity when a selected relation is not materialized.
Quest identity resolution and semantic relation materialization are exposed separately. Full quest
detail remains owned by P7-T03.

### Trainers

Creature detail exposes P4 trainer relations for the native entry, preserving `direct` vs `template`,
nullable creature resolution, trainer template ID, learning proof/wrapper spell and trainer
requirements/cost. Full recipe detail remains owned by P7-T04.

No unresolved trainer row is converted into a fabricated direct fact.
