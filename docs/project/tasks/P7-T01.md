## Goal

Turn the validated P6 migration-14 item-template/stat projection into the first stable P7
consumer-facing query contract with deterministic filtering/sorting, selected-fact provenance and
explicit partial-coverage semantics.

## Validated scope

P7-T01 delivers:

- canonical item ID/name universe;
- quality, class/subclass and inventory type filters;
- item/required level ranges;
- armor, durability and six resistance minima;
- repeatable raw stat-type/value minima;
- explicit `known_match` / `known_non_match` / `unknown` predicate semantics;
- explicit template/stat coverage state;
- deterministic sorting with unknown sort values last;
- bounded output (`1..1000`) with exhaustive state summary counts;
- selected `template.*` provenance trace;
- deterministic JSON-friendly library representation;
- read-only module CLI: `python -m octogamedb.item_query_cli`;
- compatibility preservation for the original P6 `query_item_templates()` surface;
- read-only Level-2 validator: `scripts/validate_p7_t01.py`.

## Coverage semantics

A canonical item without a migration-14 `item_templates` row has unknown template/stat coverage.
Missing projection is never interpreted as a negative game fact.

For a materialized template, P6's complete ten-slot stat contract means an absent requested raw stat
type is a known non-match. For an unmaterialized template, the same predicate is unknown.

Combined predicates use conservative three-valued conjunction: known false dominates; otherwise
unknown dominates; otherwise the item is a known match.

## Constraints retained

- no canonical DB mutation;
- no schema migration;
- no new global source priority;
- no fallback/default facts;
- no automatic acquisition/promotion;
- protected/competing P6 provenance semantics are unchanged;
- weapon damage/speed/block, item effects/tooltips, scores, saved searches, acquisition traversal and
  UI remain outside this task.
