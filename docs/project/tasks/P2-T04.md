# P2-T04 — pfQuest-turtle effective item/acquisition reconciliation

**Status:** VALIDATED

## Goal

Reconcile the P2-T03-supported item/acquisition facts against the active installed
`pfQuest + pfQuest-turtle` effective view without broadening the P2 domain.

Bounded facts:

- item identity/name;
- direct creature loot `U`;
- direct game-object loot `O`;
- one-level reference loot `R` plus refloot `U`/`O` members;
- vendor `V` and source `maxcount`.

## Source behavior established before implementation

Reviewed primary sources:

- `shagu/pfQuest` at `104f35678ca39ab1fb78b655f815cc7016f5e0c8`;
- `KameleonUK/pfQuest-turtle` at `5b8eeeeb4119be9d075087f0f0e08c187b35ad61`.

Relevant Turtle load order is:

```text
pfQuest dependency/base data
-> init/data-turtle.xml
-> init/enUS-turtle.xml
-> overwrites.lua
-> patchtable.lua
```

Relevant Turtle P2 files are:

```text
db/items-turtle.lua
db/refloot-turtle.lua
db/enUS/items-turtle.lua
db/enUS/units-turtle.lua
db/enUS/objects-turtle.lua
```

`patchtable.lua` is top-entry replacement, not recursive merge:

- value `"_"` removes the base entry;
- every other patch value replaces the full base entry.

The reviewed source contains real `"_"` removals in item/refloot data and direct item-table mutation in
`overwrites.lua`, so both behaviors are required rather than hypothetical.

pfQuest's `SearchItemID` first checks the item data entry. Name lookup separately iterates the
localized item table. Therefore item-data presence and item-name presence are not conflated.

## Architecture decision

D-026 remains bounded to P1 world reconciliation. P2-T04 adds D-027 instead of silently generalizing
that decision.

D-027 introduces only these P2 complete source-view facts:

```text
item_presence
item_acquisition_set
loot_reference_presence
loot_reference_member_set
```

Existing individual relation/name facts remain the source of attribute-level audit/query provenance.
Turtle can supersede only default/base pfQuest selections in this bounded family. Explicit/custom
selections remain protected even when their selected observation still uses source key `pfquest`.

No schema migration is required.

## Implementation

Added:

```text
src/octogamedb/importers/pfquest_item_overlay_reconcile.py
```

CLI added:

```text
python -m octogamedb reconcile-pfquest-turtle-items <pfQuest> <pfQuest-turtle> --db <db> --json
```

The reconciler:

1. requires a succeeded base `import-pfquest-items` batch at the same base revision;
2. validates the installed Turtle P2 load layout and patchtable semantics;
3. hashes the exact Turtle P2 composition inputs for a deterministic local source revision;
4. composes base + Turtle tables after supported direct literal overwrites;
5. records base and Turtle complete-set evidence separately;
6. records/selects Turtle individual U/O/R/V/name/member evidence only where policy permits;
7. materializes relation-only effective enUS targets without a fake spawn;
8. removes stale managed-pfQuest canonical relations only when the selected complete set excludes
   them;
9. retains explicit/non-pfQuest selected stale relations and reports them in
   `protected_stale_relations`;
10. preserves missing ref/source identity warnings rather than fabricating data; direct/vendor
    acquisition targets with no identity are retained as provenance, reported under
    `unresolved_acquisition_targets`, and skipped from FK-backed materialization.

A Turtle localization removal that leaves supported acquisition data is rejected as ambiguous under
the current `items.name NOT NULL` canonical model rather than guessed.
