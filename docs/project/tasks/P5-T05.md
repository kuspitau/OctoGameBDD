> For each one-sided spawn membership, which of the base, Turtle-active and Octo-comparison source

## Goal

Add a deterministic read-only audit that classifies every P5-T04 one-sided spawn membership against
three source/effective views:

```text
B = pfquest base complete spawn set
A = active selected complete spawn set
C = pfquest-octo comparison complete spawn set
```

For the 22,295 members where `A != C`, the only valid one-sided vectors are:

```text
B A C

1 1 0  -> base_active_not_comparison
0 1 0  -> active_only_vs_base
1 0 1  -> base_comparison_not_active
0 0 1  -> comparison_only_vs_base
```

P5-T05 is an attribution audit. It does not decide which source is globally authoritative.

### Base-view absence reconstruction

P1-T04 persists base `spawn_set` observations for every creature/gameobject template present in the
base pfQuest world. Therefore a Turtle-only parent can legitimately have no per-parent base
`spawn_set` row at all.

P5-T05 handles that case conservatively:

- if a unique base `spawn_set` exists, use it directly;
- if no base `spawn_set` exists and the parent is explicitly base-present, fail closed;
- if no base `spawn_set`/presence exists, infer an empty base set only when a succeeded
  `pfquest-overlay-reconcile/1-base-evidence` batch proves the complete base source view for the
  exact base revision;
- preserve the evidence mode on each attributed member.

This allows `B=0` to be reconstructed from persisted provenance without pretending that arbitrary
missing observations are negative truth.

## Secondary source-local coordinate analysis

Only two pattern pairings can represent a source-local remove/add replacement relative to base:

```text
comparison_side_possible_replacement
  active:     base_active_not_comparison
  comparison: comparison_only_vs_base

active_side_possible_replacement
  active:     active_only_vs_base
  comparison: base_comparison_not_active
```

For each class, candidate pairs require the same parent and the same compatible coordinate context
used by P5-T04. The output records:

- eligible member count;
- zero/one/multiple compatible-candidate cardinality;
- zero/one/multiple nearest-tie cardinality;
- compatible candidate pair count;
- unique-nearest candidate pair count;
- mutual-nearest candidate pair count;
- compatible, nearest and mutual-nearest distance bands;
- bounded pair details with exact distance and nearest flags.

The analysis preserves ties and rejects cross-zone or incompatible coordinate spaces. Candidate
pairs are possibilities only; no spawn identity equivalence is created.

## Important semantic constraints

- `spawn_set` membership is a set of unique `spawn_key` values.
- Repeated identical `spawn_key` payload rows must not invalidate a parent.
- Primitive `position` or `respawn_seconds` observations are not membership rows.
- Absence from one complete source view is source-view evidence, not universal game non-existence.
- Canonical D-025 geography is grouping/context evidence only.
- `pfquest-octo` remains comparison evidence under D-026.
- No authority inference follows automatically from the four pattern counts.
