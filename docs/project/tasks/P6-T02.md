## Implemented coverage report

The deterministic read-only report separates:

- cache membership from canonical identity;
- cache-only native IDs from known canonical IDs;
- canonical cache misses as unknown only;
- field/distribution coverage from canonical materialization;
- present WDB state from an initially absent/clean cache state.

It reports class/subclass, quality, inventory type, level/restriction and already-adopted P6-T01 field
coverage plus parser diagnostics and representative IDs.

The clean-cache corrective path explicitly supports an absent `itemcache.wdb` without creating a
synthetic file.

## Implemented bounded probe

The client addon accepts only explicit known candidate IDs and processes one outstanding ID at a time.
Validated parameters are:

```text
poll interval       = 0.20 s
retry interval      = 3.0 s
timeout per ID      = 15.0 s
maximum attempts    = 5
maximum IDs/run     = 20
```

Per-ID states distinguish pre-existing cache, successful post-query load and timeout/unknown. The
external validator records pre/post raw WDB hashes and machine-readable SavedVariables evidence.

No arbitrary numeric ID range is scanned.

## Freshness classes accepted

```text
refresh_proven_direct_observation
session_observed_freshness_limited
historical_cache_only
unknown
```

Only a pre-probe cache miss + current-session `loaded_after_query` + post-session raw WDB record is
`refresh_proven_direct_observation`.

A timeout remains unknown. An already-cached item remains historical-cache evidence unless a future
mechanism proves an actual refresh.

## Accepted interpretation

P6-T02 proves both of the following:

1. spontaneous cache coverage is partial and cannot be treated as an exhaustive current Octo item
   database;
2. a known canonical item absent from the preflight cache can be acquired with strong current-session
   proof under the bounded D-037 mechanism.

The 2/5 unknown outcomes remain unknown and are not transformed into item non-existence or negative
field evidence.
