# P3-T04 — quest objectives and objective geography

**Status: READY_FOR_IMPLEMENTATION**

## Goal

Add the next bounded P3 fact family: quest objective targets and the geography that can be derived
from those primitive targets.

Do not bundle rewards, item-started quest acquisition, arbitrary quest text, or quantity semantics
that are not actually present in the reviewed objective source contract.

The pinned pfQuest extractor already shows that `quest.obj` can contain these source-shaped families:

```text
obj.U   creature objective targets
obj.O   game-object objective targets
obj.I   item objective targets
obj.IR  item-use / item-required-target objective references
obj.A   area-trigger objective targets
obj.Z   zone/area objective targets
```

The same extractor also emits an auxiliary `quests-itemreq` dataset that maps involved item IDs to
creature/game-object target IDs and associated spell IDs where pfQuest inferred such target-use
requirements. P3-T04 must inspect runtime consumers and the full exporter path before assigning exact
canonical semantics to `IR` or `quests-itemreq`.

Important source-shape constraints already visible and needing confirmation:

- the exported `obj` lists are membership lists, not obvious objective-count/quantity records;
- `ReqCreatureOrGOId*` sign distinguishes creature vs game-object targets before export;
- item objectives can arise from both `ReqItemId*` and `ReqSourceId*` plus source-side inference;
- provided/source quest items and item-started quest items receive special filtering in the exporter;
- spell/item target inference can add creature, game-object, area-trigger or zone context;
- Turtle can replace whole quest data entries, so P3-T04 needs its own complete-view/reconciliation
  policy rather than silently reusing D-028 or D-030 beyond their bounded fact families.

## Expected canonical direction

The exact schema is intentionally not fixed before source inspection, but implementation should favor
explicit domain relations over a polymorphic catch-all table when semantics differ materially.

Likely primitive families include:

```text
Quest -> objective Creature
Quest -> objective GameObject
Quest -> objective Item
Quest -> objective AreaTrigger / Zone
Quest -> item-use objective relation (if source semantics justify it)
```

Objective geography should normally be derived through existing canonical relations:

```text
Quest -> objective Creature/GameObject -> Spawn -> Zone -> Map
Quest -> direct objective Zone (when obj.Z is authoritative)
```

Do not persist one simplistic `quest.zone_id` as a substitute for these relations.

## Provenance and Turtle requirements

Follow the established P3 pattern:

- preserve source-shaped objective evidence;
- introduce a task-specific complete objective-set fact if primary-source composition requires one;
- keep primitive member provenance separate from complete-set membership evidence;
- protect explicit/custom canonical selections;
- remove stale managed materialization only when the selected complete effective view excludes it;
- never delete source observations merely because canonical materialization changes;
- keep missing target IDs in explicit unresolved diagnostics instead of fabricating identities;
- same-revision reruns must be idempotent.

Do not silently generalize D-028 (`quest_presence` / endpoint set) or D-030
(restrictions/dependency sets) to objective facts.

## Query/read-model acceptance target

Extend quest queries so a representative quest can expose:

- objective subtype and native target ID;
- resolved target name when a canonical identity exists;
- derived spawn/zone/map context for creature/game-object objectives;
- direct zone/area context when source-backed;
- item-use target context where justified by `quests-itemreq` semantics;
- selected source/revision/policy provenance;
- explicit unresolved target state when identity/geography cannot be materialized.

The output must make primitive facts distinguishable from derived geography.
