### 5. Windows-safe D-029 behavior

P6-T05 retains the validated copy-before-lock protocol:

1. verify the exact selected migration-14 baseline and reject SQLite sidecars;
2. remove/replace the previous `_bak`;
3. record `PRAGMA data_version` plus file size/mtime;
4. raw-copy canonical to `_bak` before acquiring the write lock;
5. SHA-verify the backup;
6. reject data-version/file-metadata/sidecar drift around the copy window;
7. acquire `BEGIN IMMEDIATE` and re-check drift before the first write;
8. perform only the incremental import/reconciliation;
9. require replay idempotence, migration 14, FK clean and integrity `ok`;
10. restore the exact backup on any required post-backup failure.

## Evidence semantics retained

Automatic selection authority remains only:

```text
refresh_proven_direct_observation
```

with an exact current raw-record SHA match.

Still excluded:

```text
session_observed_freshness_limited
historical_cache_only
unknown
```

A retained old refresh proof can participate only when its proven raw bytes exactly equal the current
WDB record. Cache-only IDs cannot fabricate canonical identity. Manual/custom/protected selections
remain protected.
