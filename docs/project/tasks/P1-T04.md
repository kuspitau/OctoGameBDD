# P1-T04 — overlay provenance/canonical reconciliation

## Goal

Persist the P1-T03 effective pfQuest world views as durable source evidence and reconcile the
active `pfQuest + pfQuest-turtle` view into the existing P1 canonical SQLite tables without
losing base-source evidence.

The task must make two previously ambiguous semantics explicit before materialization:

1. an overlay deletion is **negative evidence about membership in that effective source view**,
   not automatic proof that the game entity can never exist;
2. a Turtle top-entry replacement replaces the entity's source-level spawn membership as a
   **complete set**, so stale pfQuest-managed canonical spawn rows must be removed when that set
   becomes canonical.

## Decisions

P1-T04 records the durable semantics in D-026.

### Source-view presence

For P1 zones, creatures and game objects, source-view membership is observed as the scalar fact:

```text
world_presence = true | false
```

`false` means that the entity is absent from that effective source view. It is negative provenance,
not a universal tombstone.

Consequences:

- a Turtle `"_"` deletion can supersede the default/base pfQuest view;
- a canonical template/zone is not physically deleted when selected non-pfQuest evidence or a
  canonical dependency still supports keeping the identity row;
- losing/older observations remain in `source_observations`.

### Complete spawn sets

For creature and game-object templates, the effective source's full spawn membership is observed
as the scalar fact:

```text
spawn_set = [deterministic spawn descriptors ...]
```

This complements the existing per-spawn `position` / `respawn_seconds` evidence. When the current
Turtle complete set is selected, canonical rows whose selected position source is managed by the
pfQuest family and which are no longer in the selected set are removed from the spawn table.
Their provenance observations remain intact.

### Selection policy

- base pfQuest complete-view facts receive only an initial/default selection when no selection
  already exists;
- the installed `pfQuest-turtle` effective view may supersede default/base pfQuest selections for
  this P1 world fact family;
- it does not silently supersede an explicit/non-pfQuest canonical selection;
- `pfQuest-octo` remains optional comparison evidence and is not automatically selected by P1-T04;
- D-025 remains authoritative for the Octo DBC map/area fact family.

No universal source priority is introduced.

## In scope

- existing P1 domains only:
  - zones;
  - creatures;
  - creature spawns;
  - game objects;
  - game-object spawns;
- the P1-T03 effective-view loaders;
- registration of separate `pfquest-turtle` and `pfquest-octo` source identities;
- deterministic source revisions for the exact P1 pfQuest/overlay file sets when requested;
- `world_presence` provenance;
- complete `spawn_set` provenance;
- canonical Turtle materialization for changed/added entries;
- stale pfQuest-family spawn cleanup for replaced/deleted sets;
- preservation of historical source observations after canonical cleanup;
- comparison-only Octo evidence;
- idempotent repeated reconciliation;
- source-shaped/core reconciliation tests and Level-2 validation against the configured local
  addon roots.

## Preconditions

The base P1 pfQuest world slice must already have been imported into the target SQLite database
with the exact `pfquest_revision` supplied to the reconciliation call.

For a fresh validation database, compute one deterministic base revision and use it consistently:

```python
base_revision = compute_pfquest_world_revision(pfquest_root)
import_pfquest_world_slice(..., source_revision=base_revision)
import_pfquest_overlay_world(..., pfquest_revision=base_revision, overlay_kind="turtle")
```

This prevents a later base re-import from re-materializing stale spawns after Turtle reconciliation.

## Out of scope

- a new schema migration;
- a generic tombstone/deletion system for every future domain;
- declaring Turtle or Octo universally authoritative;
- automatic canonical selection of optional `pfQuest-octo` evidence;
- quests/items/loot/recipes;
- full-world/P6 performance work;
- arbitrary Lua execution beyond the P1-T03 loader contract.

## Local path contract

Reuses the P1-T03 configuration:

```toml
[source_paths]
pfquest = "..."
pfquest_turtle = "..."
```

Optional comparison source:

```toml
pfquest_octo = "..."
```

No new machine-specific path key is introduced.

## Acceptance criteria

1. No new migration is required.
2. Base pfQuest, Turtle and optional Octo remain distinct registered sources/revisions.
3. Removed effective-view entries produce durable `world_presence = false` evidence.
4. Negative presence does not delete an entity supported by a selected non-pfQuest fact.
5. Creature/game-object complete spawn membership is represented by deterministic `spawn_set`
   evidence.
6. Selecting the Turtle set removes stale pfQuest-family canonical spawn rows but does not remove
   their provenance observations.
7. Turtle additions/changes materialize using currently selected canonical scalar facts, so an
   explicit non-pfQuest selection is preserved.
8. `pfQuest-octo` imports evidence only and does not mutate canonical world rows automatically.
9. Repeating the same reconciliation is idempotent: no additional canonical insert/update/delete
   is reported on the second run.
10. Existing coordinate-space semantics and D-025 DBC authority are unchanged.
