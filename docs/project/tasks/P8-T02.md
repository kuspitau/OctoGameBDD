## Why this task existed

The first real browser validation of P8-T01 proved the read-only zone explorer and its P7 semantics,
but exposed concrete interaction problems:

- pressing Enter in zone/map search inputs did not submit the query;
- sort/state-control changes appeared inert until the separate `SEARCH` button was clicked;
- zone navigation was duplicated as a large wall of links below the table;
- detail reads were visibly multi-second, so loading feedback needed to remain obvious.

These were UI ergonomics problems, not P7/domain/canonical-model defects.

## Validated implementation

P8-T02 keeps one shared `search()` action and preserves the P8-T01/D-038 layering:

```text
NiceGUI UI
  -> presentation adapter
  -> validated P7 query functions
  -> SQLite URI mode=ro + query_only=ON
```

The validated UI behavior is:

- Enter in Zone ID, zone name, Map ID and map-name fields invokes the same search action as Search;
- sort field, descending direction, `Include unknown`, and `Include known non-matches` automatically
  rerun the same query action;
- the interaction model is stated explicitly in the search card;
- the separate post-table wall of `Open <zone> (...)` links is removed;
- the zone table has a table-native `Open` action column;
- the table action emits only the current row's `zone_id`; Python `ui.navigate.to()` owns navigation;
- stable NiceGUI markers cover the tested search/state/action controls;
- visible `Loading zone detail…` feedback remains and notes that the validated P7 detail read may take
  several seconds.

No canonical-domain SQL was added to `ui_app.py`. `ui_read.py`, P7 query semantics, coverage semantics,
SQLite access, schema, migrations and canonical selection remain unchanged.
