# P8-T02 — zone explorer interaction polish

Status: `READY_FOR_IMPLEMENTATION`

Depends on: `P8-T01 VALIDATED`

## Why this task exists

The first real browser validation of P8-T01 proved the read-only zone explorer and its P7 semantics,
but exposed a small set of concrete interaction problems:

- pressing Enter in zone/map search inputs does not submit the query;
- sort/state-control changes appear inert until the separate `SEARCH` button is clicked;
- zone navigation is duplicated as a large wall of links below the table rather than being integrated
  naturally into the results table;
- detail reads are visibly multi-second, so loading feedback must remain obvious.

These are UI ergonomics problems. They do not justify changing P7 query contracts, adding canonical
SQL to the UI, mutating SQLite, or introducing a cache/API architecture.

## Bounded implementation goals

### 1. Form submission

Make Enter in the zone search form execute the same search operation as the `SEARCH` button.

Requirements:

- no duplicate query implementation;
- one shared search callback/action;
- Enter must work from zone ID, zone name, map ID and map-name inputs;
- invalid numeric input must keep the existing clear error behavior rather than crashing the page.

### 2. Sort/state control application

Remove the current ambiguity where a changed control looks like it should already affect the table.
Choose one explicit interaction model and make it consistent:

- either relevant sort/state controls automatically rerun the query; or
- the UI clearly communicates that changes are pending until an Apply/Search action.

Prefer automatic application for lightweight control changes if NiceGUI event behavior stays simple and
deterministic. Avoid issuing duplicate/re-entrant reads from one user action.

### 3. Table-native zone navigation

Replace the large separate list of `Open <zone> (...)` links with a table-native navigation affordance.
Acceptable examples include a dedicated action column or row interaction supported cleanly by NiceGUI.

Requirements:

- zone ID/name remain visible in the table;
- navigation remains keyboard/mouse understandable;
- tests have a stable marker/selector and must not rely on simulated `QTable` cell text being exposed as
  ordinary page text;
- do not add JavaScript business logic that bypasses the Python route/service contract.

### 4. Loading clarity

Preserve visible loading feedback for multi-second detail reads. Small wording/layout improvements are
in scope; query optimization, persistent caching, materialized derived tables and API splitting are
not.

## Architecture constraints

P8-T02 must preserve P8-T01/D-038:

```text
NiceGUI UI
  -> presentation adapter
  -> validated P7 query functions
  -> SQLite URI mode=ro + query_only=ON
```

Do not:

- add canonical-domain SQL to `ui_app.py`;
- mutate or migrate the canonical DB;
- collapse `known_match`, `known_non_match`, and `unknown`;
- reinterpret empty results as universal negative evidence;
- broaden into maps, dungeons, inventory, saved-query persistence or economics.
