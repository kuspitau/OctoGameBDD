## Goal

Explain the **source-native semantic divergence** between pfQuest-turtle and pfquest-octo when both
replace the same base parent.

P5-T08 should determine whether common-parent divergence is primarily:

1. different exact spawn memberships;
2. different non-spawn top-entry fields;
3. both;
4. attributable to source-family-specific content classes or routed-zone classes.

This task is a read-only audit. It does not choose source authority.

## Fixed population

Start from the P5-T07 parent population satisfying:

```text
active raw transformation     = overlay_whole_entry_replaced
comparison raw transformation = overlay_whole_entry_replaced
```

P5-T07 measured exactly 1,085 such parents and 1,085 different raw replacement payload hashes.

Do not silently expand to unrelated parents. Any broader population must be reported separately and
must not replace the fixed routed population.

## Required exact set analysis

For every fixed parent, reconstruct exact deterministic spawn-key sets:

```text
B = base effective spawn set
A = active/Turtle effective spawn set
C = comparison/pfquest-octo effective spawn set
```

At minimum classify `A` versus `C` as exactly one of:

- `active_equals_comparison`;
- `active_strict_superset`;
- `comparison_strict_superset`;
- `partial_overlap`;
- `disjoint`.

Also retain exact cardinalities:

```text
|B| |A| |C|
|A ∩ C|
|A - C|
|C - A|
|A - B|
|C - B|
|B - A|
|B - C|
```

No coordinate-distance matching is allowed. Equality/membership uses the established deterministic
`spawn_key` only.

## Required raw payload analysis

For each parent determine whether the active/comparison raw replacement payload difference is:

- spawn-membership only;
- localization/name only;
- other top-entry fields only;
- spawn plus other fields;
- unsupported/unclassified.

Reuse existing P1/P5 source-native parsing and composition semantics. Do not invent a second overlay
composition model.

If the raw payload contains fields whose semantics are not already understood by the project, report
them explicitly and fail closed for any interpretation that would affect classification.

## Required stratification

Aggregate by at least:

- parent subject kind (`creature`, `gameobject`);
- P5-T06 base-parent class;
- routed-zone contribution (406, 5602, 5581, 1584);
- whether the parent contributes active-only, comparison-only or both-source one-sided members in the
  routed slice;
- `A` versus `C` set-relation class;
- raw payload difference class.

Keep Stonetalon Mountains / Blackrock Depths distinguishable from Grim Reaches / Northwind because
P5-T07 measured both-source contributions only in the former two routed slices.

## Expected routing outcomes

Closeout should use measured results to choose a bounded next step, for example:

1. one source is consistently a strict spawn-set superset for a well-defined relation/content class ->
   bounded field/relation-specific authority review;
2. divergence clusters by custom-zone/source-family semantics -> separate ingestion/authority policy
   by content class;
3. differences are dominated by non-spawn raw fields -> route the specific field semantics before
   spawn authority;
4. A/C overlap is structurally mixed with no stable class -> preserve both as conflicting provenance
   and avoid authority promotion.

Do not preselect an outcome during implementation.
