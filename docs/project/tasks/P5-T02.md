## Goal

Provide a deterministic, read-only audit/drill-down surface that exposes enough evidence to explain
why a single-value observation group has no canonical selection, without fixing or selecting it.

## Implemented scope

### CLI/API

The generic audit layer provides:

```text
unselected_report(...)
```

and:

```text
python -m octogamedb unselected \
    [--subject-kind KIND] [--subject-key KEY] [--fact FACT_KEY] \
    [--source SOURCE_KEY] [--limit N] [--db PATH] [--json]
```

`--source` means “keep candidate groups containing at least one observation from this source”; once a
group matches, all of its observations remain visible so cross-source provenance is not hidden.

`--limit` bounds only detailed drill-down groups. All aggregates cover the complete filtered candidate
set. `--limit 0` is summary-only and is the expected full-data capture mode.

### Candidate identity

A group is included only when all of these are true:

- it has no row in `canonical_selections`;
- it has at least one source observation;
- `COUNT(DISTINCT source_observations.value_json) = 1`.

This preserves the existing P0/P5 canonical-JSON conflict identity. A group with multiple observations
that all encode the same canonical JSON value remains a single-value group.

### Aggregate evidence

The report returns deterministic:

- counts by subject kind;
- counts by `(subject_kind, fact_key, fact_kind)`;
- contributing source counts;
- source/revision counts;
- `(subject_kind, fact_key, fact_kind, source_key)` cross-tabs;
- source/revision/import-batch-status counts;
- correlated subject/fact patterns with subject count and group count.

The source/revision/family/batch aggregates are derived from one candidate-evidence SQL pass rather
than repeatedly scanning the complete provenance graph.

### Drill-down evidence

Each returned detailed group includes:

- subject kind/key;
- fact key/kind/instance;
- sole parsed value;
- observation IDs;
- source key/revision;
- source record type/raw identifier;
- confidence/authority tier;
- linked import batch IDs/statuses;
- all sibling observation groups on the same subject;
- sibling group state (`selected`, `single_value_unselected`, `conflict_unselected`, or
  `empty_unselected`);
- selected sibling policy and selected source where present;
- compact classification-evidence summaries of those siblings/sources/revisions/batches.

### Classification behavior

The report exposes the required vocabulary:

1. `expected_non_canonical_evidence`;
2. `effective_view_exclusion`;
3. `coverage_reconciliation_gap`;
4. `policy_gap`;
5. `unresolved`.

The implementation intentionally assigns **`unresolved` to every candidate**. Generic provenance alone
does not prove importer/reconciler intent, so automatically choosing one of the first four labels would
violate the task's non-guessing requirement. The aggregate and sibling evidence is provided so the
real P1/P4 dataset can support that classification at closeout.

No canonical winner is selected.

## Closeout classification

The four required P5-T02 classes are resolved as:

```text
expected_non_canonical_evidence = 9880
effective_view_exclusion        = 0
coverage_reconciliation_gap     = 0
policy_gap                      = 0
```

This classification follows directly from combining the validated source aggregate with the accepted
P1 reconciliation contract:

- P1-T04 persists `pfquest-octo` as an optional comparison source;
- P1-T04 explicitly does not automatically select or materialize that source into canonical P1 world
  rows;
- D-026 records that optional `pfquest-octo` remains comparison evidence unless explicitly selected;
- P5-T02 proves every currently unselected single-value group comes from that source and no other
  source.

Therefore the absence of canonical selections for these groups is expected by existing policy. No
coverage/reconciliation bug or missing selection policy is exposed by P5-T02.

`effective_view_exclusion` is not used as the closeout class for these groups even when a particular
Octo comparison subject differs from or is absent from the active Turtle view: that describes the
**content relationship between source views**, while the reason the observation is unselected is the
stronger existing comparison-only source contract. P5-T03 is routed specifically to measure those
content differences.
