# P5-T02 — Unselected single-value provenance audit

## Status

`READY_FOR_IMPLEMENTATION`

## Motivation

P5-T01 validated the cumulative migration-13 provenance-resolution baseline and found:

```text
observation_group_count             = 1307532
selected_group_count                = 1297652
unselected_group_count              = 9880
conflict_group_count                = 64512
resolved_conflict_group_count       = 64512
unresolved_conflict_group_count     = 0
unselected_single_value_group_count = 9880
empty_observation_group_count       = 0
```

Therefore the next measured resolution gap is not unresolved conflict handling.

All 9,880 unselected groups contain one distinct value and require explanation before any selection
policy is changed.

## Measured family distribution

```text
creature.faction                         = 4
creature.level_max                       = 1
creature.level_min                       = 1
creature.name                            = 1
creature.spawn_set                       = 1
creature.world_presence                  = 1

creature_spawn.position                  = 2748
creature_spawn.respawn_seconds           = 2748

gameobject.faction                       = 5
gameobject.name                          = 2
gameobject.spawn_set                     = 2
gameobject.world_presence                = 2

gameobject_spawn.position                = 2182
gameobject_spawn.respawn_seconds         = 2182
```

The distribution sums exactly to `9880`.

The overwhelming majority are paired spawn facts (`position` + `respawn_seconds`), so P5-T02 should
make correlated subject/fact gaps easy to inspect rather than treating all 9,880 rows independently.

## Goal

Add a deterministic, read-only audit/drill-down surface that explains why a single-value observation
group has no canonical selection.

For each relevant group, the project should be able to inspect at least:

- subject kind/key;
- fact key/kind/instance;
- the sole distinct observed value;
- observation IDs;
- source key/revision;
- import-batch linkage/status;
- whether sibling facts for the same subject are selected or unselected;
- existing selection policy/source on comparable sibling groups where useful;
- aggregate counts by subject/fact family and source.

The purpose is to classify the gap, not to fix it yet.

## Required classifications / questions

P5-T02 must provide enough evidence to distinguish at least:

1. **expected non-canonical evidence** — an observation intentionally retained only for provenance;
2. **effective-view exclusion** — source evidence exists but the effective/canonical source view
   intentionally excludes that subject/fact;
3. **coverage/reconciliation gap** — the importer/reconciler failed to create a selection that the
   existing policy contract would otherwise require;
4. **policy gap** — evidence is valid and should probably be selected, but no current policy covers
   the case.

If the data cannot support one of those labels automatically, report the evidence and leave the
classification unresolved rather than guessing.

## Scope

### Included

- a deterministic read-only report/API/CLI for unselected single-value groups;
- aggregate counts by subject kind, fact key/kind and source;
- drill-down to concrete subject/fact groups;
- optional filters sufficient to isolate the measured P5-T01 families;
- source revision/import-batch provenance;
- correlated inspection for repeated unselected facts on the same subject;
- fixture/golden tests distinguishing selected, conflicting-unselected and single-value-unselected
  cases;
- deterministic JSON output suitable for Level-2 capture.

### Explicitly excluded

- no migration;
- no canonical DB mutation;
- no automatic canonical selection;
- no source-priority change;
- no rewriting existing reconciliation policies;
- no bulk "select all single-value groups" behavior;
- no domain-specific fix before the report identifies the actual cause.

Any later task that changes canonical-selection behavior must update the appropriate decision/contract
documentation explicitly.

## Expected implementation direction

Prefer extending the existing generic audit layer rather than creating a source-specific ad hoc script.

A likely surface is either:

```text
python -m octogamedb unselected ...
```

or a clearly bounded extension of:

```text
python -m octogamedb resolution ...
```

The exact CLI spelling may be adjusted if repository conventions favor another shape, but the output
must be deterministic and machine-readable.

## Level-1 acceptance

Use small provenance fixtures to cover at least:

- one selected single-value group — excluded from this report;
- one unselected single-value scalar group — included;
- one unselected single-value relation group — included;
- one unresolved conflict — not misclassified as single-value;
- multiple observations with identical canonical JSON value — still one distinct value;
- source/revision/import-batch provenance;
- subject-kind/fact/source filters;
- deterministic ordering and JSON output;
- correlated sibling facts for one subject.

Existing `source`, `trace`, `conflict`, `coverage`, and `resolution` tests must continue to pass.

## Level-2/full-data acceptance

Run against an isolated snapshot/copy of:

```text
data/generated/octogamedb.sqlite3
```

with expected canonical baseline SHA-256:

```text

```

Acceptance must confirm:

```text

unresolved conflicts                 = 0
empty observation groups            = 0
```

The aggregate family distribution must reproduce the P5-T01 counts exactly unless an intentional
tracked-code change before validation legitimately changes the baseline.

The report must capture enough detail to explain the 2,748 creature-spawn subjects and 2,182
gameobject-spawn subjects that appear as paired `position`/`respawn_seconds` gaps, plus the small
creature/gameobject template remainder.

The validation must use a copy/snapshot and prove the canonical DB SHA-256 is unchanged before/after.

## Closeout decision

P5-T02 closeout must record which of the four classification classes actually explain the 9,880
groups.

Only then should the next P5 task decide whether to:

- change a selection policy;
- correct an importer/reconciler coverage bug;
- explicitly document expected non-canonical evidence;
- or leave some classes intentionally unselected.
