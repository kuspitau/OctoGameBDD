## Implemented semantics

The comparison states are:

```text
comparison_only
active_only
same_value
different_value
not_directly_comparable
```

P1-T04 persists `pfquest-octo` as a delta from the base pfQuest effective view. Therefore missing Octo
scalar/template observations are not interpreted as absence.

The implementation uses:

- `world_presence` as explicit complete presence context for template-level absence/presence;
- `spawn_set` as complete membership context for child spawns;
- canonical JSON identity for directly comparable values;
- persisted source revision/import-batch provenance;
- selected source/revision/policy context for the active side.

Historical selected scalar/spawn observations excluded by active `world_presence` / `spawn_set` are
not treated as active effective evidence.

D-026 remains unchanged.

## Closeout decision

P5-T03 found no evidence strong enough to justify an immediate `pfquest-octo` authority promotion,
global source-priority change, or D-026 rewrite.

The dominant meaningful discrepancy is spawn membership:

- 2,570 differing parent `spawn_set` values;
- 22,295 unique one-sided spawn memberships;
- zero coordinate differences for shared spawn identities;
- only 21 shared respawn-time differences.

However, spawn identity itself contains coordinate information. A source-side coordinate move can
therefore appear as one `active_only` spawn plus one `comparison_only` spawn rather than as a
`position different_value`.

The next task must characterize that possibility before interpreting every membership difference as a
true spawn addition/removal.
