## Source investigation result

P6-T01 adopts the Octo client `itemcache.wdb` as the direct source for the first bounded template/stat
family. A supported record is a cached `SMSG_ITEM_QUERY_SINGLE_RESPONSE` received by the client from
the connected server and is therefore direct Octo client/server-observed evidence. The 1.12 record
layout was checked against wowdev WDB documentation and VMaNGOS `ItemHandler.cpp` at commit
`e3722f19171c45d97e6741b4f2e43686c761b8b0`.

Critical completeness rule:

> `itemcache.wdb` is partial-positive across item IDs. A missing cache record is unknown, never negative
> evidence and never authorizes canonical cleanup.

The complete ten stat slots of a present supported record are modeled as a complete-set observation.
A cache hit is direct observed evidence, but an arbitrary pre-existing cache does not prove freshness;
that limitation is now part of the accepted D-036 contract and routes P6-T02.

Other considered families remain non-universal and field-specific:

- OctoDB: candidate/corroboration until a stable structured revision/completeness contract is
  established for the relevant item fields;
- pfQuest base: existing item identity/acquisition source, not a P6 template/stat truth source;
- `pfquest-turtle`: existing overlay evidence, but P6-T01 does not reinterpret it as template truth;
- Tortoise/CMaNGOS/VMaNGOS-style data: possible lower-authority fallback coverage only after a specific
  data adapter/revision is accepted; VMaNGOS is used here only as a protocol-layout reference.

No universal source priority is introduced.

## Implemented bounded fact family

P6-T01 implements:

- class/subclass;
- quality;
- raw inventory/equipment type;
- item level / required level;
- allowable class/race masks;
- required skill/rank, spell and reputation fields;
- armor and six resistances;
- maximum durability;
- all ten ordered raw stat slots.

Weapon damage/speed, block, item effects/spells, tooltip text and icon/display semantics remain deferred
instead of being flattened or guessed.

## Implementation

Migration:

```text
src/octogamedb/db/migrations/0014_item_template_facts.sql
```

Validated schema projections:

```text
item_templates
item_stat_modifiers
```

Importer:

```text
src/octogamedb/importers/octo_itemcache.py
```

Importer properties:

- requires an explicit bounded native item-ID set;
- parses supported Vanilla 1.12 WDB records deterministically and fails closed on unsupported shape;
- creates a deterministic revision hash from WDB header semantics plus only the requested records;
- records each scalar as `template.<field>` and the complete stat set as `template.stat_slots`;
- uses direct Octo authority tier `0` for the supported fact family;
- preserves competing observations;
- replaces only known managed P6 selections when field authority permits;
- protects unknown/manual/custom selection policies;
- never creates placeholder canonical item identities for cache-only IDs;
- treats missing requested cache IDs as warnings/unknown observations, never deletions;
- is idempotent for an unchanged bounded slice.

Query proof:

```text
src/octogamedb/item_search.py
```

It can combine a maximum required level, raw inventory type and multiple raw stat-type minima and
returns selected source revision/policy/reason trace information for each result.
