## Goal

Turn the already-validated P3 quest-domain read models into a stable bounded consumer-facing
search/exploration layer without redesigning the P3 canonical model.

The task should make it practical to answer questions such as:

```text
Which quests are relevant to this zone/map?
Where are they given and finished?
Which objectives happen here or elsewhere?
What prerequisites/follow-ups connect them?
Which items are explicitly required or rewarded?
Which facts are unresolved or have unknown geography?
```

This is the next bounded step toward later dungeon/zone quest views and chain-oriented exploration.
It is not yet a generalized dungeon-classification system or graphical quest planner.

## Required scope

At minimum, design and test a stable read-only library/CLI layer that can:

- search canonical quests by native quest ID and case-insensitive title text;
- filter by known quest level and minimum player level where those scalars are materialized;
- expose raw race/class masks without inventing labels unless an existing validated mapping is reused;
- expose giver and finisher endpoints separately, including source identity/name and derived locations;
- expose objective subtypes separately, with their existing resolved/unresolved state and geography;
- positively filter by known giver, finisher and/or objective zone/map geography;
- preserve a quest whose relevant endpoint/objective exists but is unlocated as known relation evidence
  with unknown geography;
- expose the selected prerequisite set with its validated `any_of` semantics;
- expose derived follow-ups separately from prerequisites;
- expose close/exclusive-group membership separately from progression;
- provide bounded prerequisite/follow-up traversal with cycle protection and deterministic ordering;
- expose explicit required items/quantities, auxiliary required-source items, provided items, guaranteed
  rewards and choose-one reward alternatives through the existing P3-T05 read model;
- retain the explicit distinction between P3-T04 item objective membership and P3-T05 required-item
  quantity facts;
- expose provenance/selection information already available from the underlying read models;
- retain unresolved target IDs and incomplete set diagnostics rather than fabricating missing entities;
- return deterministic bounded output and a JSON-friendly CLI representation.

The implementation may add a new focused query module/CLI or extend an existing quest read surface,
whichever keeps responsibilities clearest after inspecting callers/tests.

## Geography semantics

A quest does not have one universal primary zone.

P7-T03 must preserve relation-specific geography:

```text
giver geography
finisher geography
creature/gameobject objective geography
item-use target geography
area-trigger geography
direct source-backed zone objective geography
```

A filter such as `--giver-zone 10` must not silently mean “quest belongs to zone 10”. Likewise an
objective in one zone does not erase a giver/finisher in another zone.

Geography derived through target spawns remains derived under D-008/D-009. Do not persist a new
`quest -> zone` primary relation merely to simplify queries.

Unlocated known endpoints/objectives remain valid relation evidence. Failure to find matching known
geography is not automatically universal proof that a quest never occurs in the requested place unless
the exact relevant selected complete-set/geography evidence proves that negative claim.

## Progression / chain semantics

P3-T03 established important constraints that P7-T03 must retain:

- `pre` is one selected prerequisite set with `any_of` semantics, not all-of;
- follow-ups are derived as the reverse of selected prerequisite membership;
- close sets are source-preserved exclusive-group member sets and are not generic progression edges;
- selected/materialized member counts and `is_complete` matter when referenced quest identities are
  unresolved.

Traversal must therefore be explicit about direction and ambiguity.

A later UI may want “chain step” numbers, but P7-T03 must **not** invent a unique linear step when the
selected graph branches, converges, contains alternatives, or is incomplete. If a useful derived depth
or route representation is added, it must:

- state the derivation rule;
- preserve multiple valid branches/alternatives;
- protect against cycles;
- expose ambiguity/incompleteness rather than flattening it away.

## Item-fact semantics

Reuse P3-T04/P3-T05 distinctions exactly:

```text
objective item membership != explicit required item quantity
required source item       != turn-in quantity
provided item quantity may be unknown
reward item                != choice reward item
choice rewards use choose-one set semantics
```

No quantity is inferred from objective membership, slot coincidence, item-ID equality or default `1`.

## Coverage / negative-evidence rule

P7-T03 is an exploration layer, not a new source authority layer.

Do not manufacture universal negative facts from missing materialization or geography. In particular:

- an endpoint/objective without a spawn does not prove the quest is absent from every zone;
- an unresolved objective/endpoint target remains unresolved evidence;
- incomplete prerequisite/close sets must not be presented as complete merely because all currently
  materialized members were traversed;
- absence of a P3-T05 required/reward row must follow the existing source-family completeness contract;
  do not introduce a broader “quest has no such item” assertion unless the underlying selected source
  evidence actually proves it.

If a requested negative/filter state cannot be represented correctly with the existing P3 provenance
and completeness information, keep it unknown/not-proven or route a separate bounded task rather than
weakening semantics.

## Constraints

- Read-only consumer task: no canonical DB mutation.
- No schema migration unless a concrete query requirement proves the current model insufficient; if
  so, stop and route a separate schema task.
- No new source ingestion/acquisition campaign.
- No new global source-priority rule.
- Preserve protected selections and competing source observations.
- Preserve native IDs and template/spawn separation.
- Do not persist a simplistic `quest.zone_id` or generalized `quest_zones` primary truth.
- Do not reinterpret `any_of` prerequisites as all-of.
- Do not treat close-group membership as progression.
- Do not infer missing item quantities.
- Keep output deterministic and bounded.

## Non-goals

P7-T03 does not implement:

- generalized dungeon/raid classification when no validated dungeon identity relation exists;
- an optimized quest route planner;
- automatic “best chain step” numbering for ambiguous graphs;
- graphical maps/UI;
- live quest completion/character state;
- ownership/inventory/bank integration;
- new quest source ingestion;
- new item-template field acquisition;
- saved searches or weighted scoring.

Those remain later bounded tasks. A later dungeon-centric view should build on the validated
relation-specific quest geography/progression surface rather than bypassing it.
