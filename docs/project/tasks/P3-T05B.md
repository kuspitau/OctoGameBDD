# P3-T05B — validate Octo live quest-query and Tortoise SQL source contract

**Status: VALIDATED**

## Goal

Refine the P3-T05 source contract after the post-P3-T05A audit identified two materially stronger
inputs:

1. direct positive quest observations obtainable from the actual Octo server/client interaction via
   ClassicAPI;
2. a current, structured Turtle 1.18.1 restoration world SQL source whose `quest_template` carries the
   quantity/reward families missing from distributed pfQuest.

P3-T05B is an acquisition/adapter/validation task. It does not add the final P3-T05 canonical schema
and must not mutate `data/generated/octogamedb.sqlite3`.

## Governing decisions

D-033 supersedes D-032 only for the **current P3-T05 source-priority/acquisition strategy**. D-032's
semantic distinctions (`ReqItem`, `SrcItem`, `ReqSource`, guaranteed `RewItem`, choice
`RewChoiceItem`) and conservative absence semantics remain applicable.

No new decision was required by this implementation. The implementation follows D-033 and preserves
source conflicts under the existing provenance/conflict rules.

## Source identities and bounded priority

Stable keys implemented/accepted by the comparator:

```text
octo-live-quest-query
octodb
tortoise-world-sql
cmangos-vanilla
```

Priority contract:

| Fact family | Preferred evidence order |
| --- | --- |
| ordinary required item + count | Octo live -> OctoDB -> Tortoise -> CMaNGOS |
| guaranteed item reward + count | Octo live -> OctoDB -> Tortoise -> CMaNGOS |
| choice item reward + count | Octo live -> OctoDB -> Tortoise -> CMaNGOS |
| provided/source item ID | Octo live -> OctoDB -> Tortoise -> CMaNGOS |
| provided/source item count | OctoDB -> Tortoise -> CMaNGOS |
| auxiliary `ReqSourceId/ReqSourceCount` | Tortoise -> CMaNGOS |

Lower-priority observations remain in comparison output. Equal-priority observations for the same
semantic fact that disagree produce `ambiguous_same_priority` rather than an arbitrary silent choice.

## Implementation

### `src/octogamedb/importers/quest_source_evidence.py`

Provides the bounded acquisition/normalization/reconciliation primitives.

Tortoise replay behavior:

- reads the pinned quest base dump;
- resolves column identity from explicit insert columns, `CREATE TABLE`, or
  `sql/create_databases.sql`;
- scans world migrations in deterministic path order and consumes only statements structurally
  targeting `quest_template`;
- supports bounded `INSERT`/`INSERT IGNORE`/`REPLACE`, literal `UPDATE ... WHERE entry =/IN`, and
  bounded deletes/truncation;
- tolerates non-row dump controls such as lock/unlock and enable/disable keys;
- fails closed on unsupported relevant expressions/mutation shapes;
- preserves fixed slot number, family, duplicate item IDs and explicit zero counts;
- does not deduplicate `ReqItem` against `ReqSource`;
- records SHA-256 for every consumed input, a deterministic content-set hash and projection hash;
- keeps a nonzero-ID/zero-count value as source evidence rather than defaulting it.

Live SavedVariables normalizer behavior:

- parses only the versioned `OQPB1|...` record strings emitted by the project probe;
- preserves positive required/reward/choice item counts;
- preserves positive `srcItemID` as ID evidence only;
- emits no live source-item-count fact;
- emits no live `ReqSource` fact;
- treats successful empty lists/zero IDs as `unknown` under the current partial-positive contract;
- treats failed requests as status/error evidence with no fabricated negative facts;
- records raw SavedVariables SHA-256, per-record hash and deterministic capture hash.

Reviewed CSV projection behavior:

- `snapshot-csv` accepts only the explicit header:
  `quest_id,fact_family,item_id,value,slot`;
- it is restricted to reviewed `octodb` or `cmangos-vanilla` representative evidence;
- it performs no prose inference and no source scraping;
- source revision/hash identity is supplied explicitly and retained.

Comparison behavior:

- selects only among sources eligible for the relevant family;
- uses D-033 field-specific priority;
- retains all evidence and reports conflicts;
- refuses to silently resolve same-priority differing values.

### `scripts/octogamedb_quest_probe/`

Contains a Vanilla-compatible addon:

```text
OctoGameBDD_QuestProbe.toc
OctoGameBDD_QuestProbe.lua
```

The probe:

- never starts a quest scan automatically;
- is triggered manually with `/oqpb <quest IDs...>`;
- accepts at most 50 unique positive IDs per invocation;
- issues at most one outstanding `RequestLoadQuestByID` at a time;
- waits for `QUEST_DATA_LOAD_RESULT` before `GetQuestDetails`;
- adds a 0.75-second gap before the next request;
- stops visibly if required ClassicAPI functions are unavailable;
- persists bounded source-shaped record strings in `OctoGameBDDQuestProbeDB`;
- records quest ID, status, UTC capture time where available, realm, client build and pinned ClassicAPI
  semantic reference revision;
- is resumable in the sense that rerunning selected IDs replaces those ID records without requiring a
  full-world scan.

The SavedVariables file is raw/local evidence and must not be committed or placed in a delta package.
