## Goal

Deliver the first stable bounded first-class zone consumer surface over already validated P1/P2/P3/P4
and P7 query contracts. Search canonical zones/maps, then inspect one zone by composing concrete known
geography for world entities, quest roles, item acquisition, recipe-learning sources, vendors and
trainers without creating a simplified primary `zone -> everything` truth.

## Architecture result

No architecture decision needed revision. The final implementation remains inside the derived/query
layer under D-008, D-009, D-019 and D-025/D-026:

- zone/map identity remains canonical;
- template and spawn identity remain separate;
- item/quest/recipe geography remains derived from owning source/role relations;
- provenance remains owned by existing selected observations;
- no source priority or complete-set policy is added;
- no schema migration or canonical DB write is performed.

## Final implementation

### Zone identity search

```text
src/octogamedb/zone_search.py
  query_zones()
  zone_query_page_to_dict()
```

Supports exact zone/map IDs, zone/map-name substring search, deterministic sort, bounded limit,
parent-zone/map identity and selected name provenance. Missing map identity/name remains explicit
`unknown` rather than false.

### One-zone inspection

```text
src/octogamedb/zone_search.py
  inspect_zone(..., entity_limit=..., recipe_limit=..., include_recipes=...)
```

The two-step search/detail design avoids broad zone search automatically triggering detail composition
for every returned zone.

For one zone the final read model composes:

- P7-T05 concrete creature/gameobject spawns and semantic roles;
- independent direct/reference/vendor item paths;
- giver/finisher/creature-gameobject objective quest roles;
- vendor creature/item roles;
- resolved direct/template trainer rows plus unresolved trainer evidence;
- compact positive recipe-learning evidence derived from the already-computed zone item/trainer/quest
  roles.

`coverage.state` remains `unknown` and `negative_claim_authorized=false` because P7-T06 defines no new
complete set for all zone contents. P7-T05's bounded complete-spawn-set negatives remain owned by that
contract and are not generalized.

`include_recipes=False` permits callers/validators to inspect the world/item/quest/vendor/trainer
projection without recipe composition.

### Compact recipe projection

The first implementation called the full P7-T04 geography query five times per zone. Real validation
showed that this caused a pathological nested scan through recipes, teaching-item acquisition and
provenance.

The validated correction adds:

```text
src/octogamedb/zone_recipe_projection.py
  project_zone_recipes()
```

It inverts positive evidence already present in the zone projection:

```text
known zone item acquisition -> teaching-item recipe identities
known resolved zone trainers -> trainer recipe identities
known giver role -> quest-learning recipe identities
known finisher role -> quest-learning recipe identities
known creature/gameobject objective role -> quest-learning recipe identities
```

The compact result retains recipe identity and the concrete zone-learning evidence that caused the
match. Missing evidence remains `unknown`; it never becomes a universal negative. Full hydrated recipe
context remains owned by P7-T04 and is fetched there by recipe ID when needed.

### Read-only CLI

```text
src/octogamedb/zone_cli.py
python -m octogamedb.zone_cli ...
```

The CLI opens SQLite using URI `mode=ro`. `--details` requires exactly one returned zone. Entity and
recipe sections retain explicit `1..1000` limits.

### Tests and accepted-canonical validator

```text

tests/test_zone_recipe_projection.py

```

Focused P7-T06 tests cover zone identity/search, unknown map semantics, sorting, multi-spawn retention,
independent item/quest/vendor/trainer roles, truncation/read-only behavior and compact recipe
projection/limit behavior.

```text

-> find_item_sources
```

was opened read-only and remained unchanged.

added progress/timing output plus `include_recipes=False` to support bounded validation passes.
