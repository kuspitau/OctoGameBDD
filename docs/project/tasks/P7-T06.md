## Goal

Add the first stable bounded **zone-first-class** consumer surface. Search canonical zones/maps and
inspect the already-validated facts and relation paths whose concrete geography resolves to the
selected zone, while preserving their distinct source/role semantics.

This is a read-only query/exploration task. It must not add a migration, new source priority, ingestion
tranche, route planner, generalized dungeon classifier or graphical UI.

## Required composition scope

### Zone/map identity

Use the existing P1 canonical zone/map hierarchy as the query universe. Support a practical bounded
search by at least:

- exact zone ID;
- zone name substring;
- exact map ID;
- map name where already canonically available;
- deterministic sorting/limit.

Keep canonical zone identity, parent-area hierarchy and map identity distinct. Do not infer dungeon,
instance, faction or access classifications that are not already validated facts.

### World entities present

Compose P1/P7-T05 spawn geography to expose creatures and gameobjects with concrete known spawns in
the zone. Preserve independent spawn instances and selected provenance.

A zone view may aggregate display/counts for convenience, but the underlying returned detail must
retain the concrete spawn/path evidence needed to audit the result.

### Quest roles

Compose P7-T03 without flattening roles. Expose separately:

- quests given in the zone;
- quests finished in the zone;
- quests with creature/gameobject objectives in the zone.

A quest that appears under multiple roles must retain each role independently. Missing/unlocated
endpoints/objectives must not be silently interpreted as absence from every zone.

### Item acquisition paths

Compose P7-T02 for acquisition paths whose **concrete source geography** resolves to the selected zone:

- direct loot;
- reference loot;
- vendor.

Keep each path independent. Do not combine probabilities and do not treat vendor metadata as drop
chance. Do not claim that an item is globally unobtainable in a zone merely because one path is
unresolved.

### Recipe learning sources

Compose P7-T04 for recipe-learning paths whose concrete source geography resolves to the selected
zone, preserving teaching-item, direct/template trainer and quest-learning semantics separately.

This is **recipe availability/learning-source geography**, not a persisted primary `recipe -> zone`
fact. Crafted output availability and recursive reagent/BOM economics remain outside this task unless
they are needed only as existing read-only context.

### Vendor/trainer roles

Expose creatures acting as vendors/trainers in the zone by composing validated P7-T05/P2/P4 evidence.
Preserve direct/template trainer semantics and any unresolved native relation evidence.

## Three-state and unknown semantics

The zone surface must remain conservative:

- positive concrete geography may prove inclusion;
- validated complete-set semantics may prove only the bounded negatives authorized by their owning
  contract;
- unresolved/missing geography remains `unknown`, not a universal negative;
- do not create a new global complete-set claim for all entities/items/quests/recipes in a zone.

For filters that depend on derived relation geography, reuse the explicit
`known_match / known_non_match / unknown` pattern where a negative can actually be proven. If no owning
contract proves a negative, return `unknown` rather than synthesizing one.

## Query/API expectations

Add a small library surface and read-only CLI consistent with P7-T01..T05 conventions. The exact
module names may be chosen during implementation, but the API must be:

- deterministic;
- JSON-friendly;
- bounded/paginated or explicitly limited;
- auditable back to the underlying source/provenance owners;
- strict SQLite read-only (`mode=ro`) for CLI access.

Avoid N+1 full-corpus query patterns. Measure/structure composition so a zone inspection remains
practical on the accepted canonical DB.

## Durable contract and tests

Implementation must add:

- a durable P7 zone-query contract document;
- focused synthetic tests covering independent roles/paths and unresolved geography;
- a read-only accepted-canonical validator that dynamically discovers representative cases;
- byte-preservation, `foreign_key_check` and `integrity_check` gates.

At minimum test:

1. zone identity/name/map search;
2. multiple independent creature/gameobject spawns;
3. quest giver vs finisher vs objective separation;
4. direct vs reference vs vendor item paths;
5. recipe teaching-item vs trainer vs quest learning paths;
6. vendor/trainer role exposure;
7. unresolved geography retained as unknown;
8. deterministic sort/limit/JSON;
9. CLI read-only behavior.

## Explicit non-goals

Do not include in P7-T06:

- a generalized dungeon/instance classifier;
- dungeon quest-chain UX or automatic dungeon grouping;
- pathfinding/routes;
- map rendering;
- weighted item scoring;
- saved searches/comparisons;
- ownership/inventory state;
- auction/economics/profit modeling;
- recursive crafting BOM analysis;
- new item-template acquisition merely to fill display gaps;
- new source authority or source merge policy.

A later bounded task can build dungeon/instance views on this zone substrate once the classification
contract is explicit.
